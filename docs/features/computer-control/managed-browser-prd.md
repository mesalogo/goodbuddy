# 浏览器自动化升级需求

状态与验证结果见[实施记录](./managed-browser-progress.md)。

## 产品目标

升级网页自动化能力，保留原有普通浏览器体验。右侧继续使用原有地址栏、导航按钮和网页区域；文字清晰度、系统缩放、输入法、鼠标和剪贴板交互保持原样。用户无需了解底层自动化框架。

AI 按任务自动操作。用户可以随时直接操作同一网页，不设置“接管”“交还 AI”模式，不显示控制权状态。页面自身的上传按钮打开系统文件选择器；下载由网页自身入口触发，工作栏不增加上传下载工具栏。

## 功能要求

| 编号 | 要求 | 验收条件 |
| --- | --- | --- |
| FR-1 | 界面保持普通浏览器布局 | 原有地址栏和网页区域；没有新增控制模式、状态条或文件工具栏 |
| FR-2 | 复用成熟自动化能力 | 使用 Playwright 快照、元素定位、自动滚动、可操作性等待和取消 API |
| FR-3 | AI 可完成复杂页面操作 | 支持键盘、悬停、拖拽、勾选、框架内表单、网页弹框、文件字段及标签管理 |
| FR-4 | 原生显示质量不退化 | 页面直接渲染；系统 DPI、网页缩放和点击位置匹配；不把低分辨率预览放大为网页 |
| FR-5 | 用户直接操作，AI 自动执行 | 无需模式切换；中文输入、选择和粘贴后，AI 读取到同一页面状态并可继续操作 |
| FR-6 | 文件交互使用网页入口 | 人工选择保留系统文件选择器；AI 可操作文件字段；已保存下载不随标签关闭删除 |
| FR-7 | 多标签和会话归属明确 | 同会话共享登录状态，页面引用独立；切换工作栏不改投模型请求；弹窗进入受管标签 |
| FR-8 | 沿用应用自带浏览器 | 不要求用户额外安装 Chrome，也不创建第二份网页来模拟右侧显示 |
| FR-9 | 取消和生命周期正确 | 被取消的等待操作不会迟到执行；隐藏面板保留页面；关闭一个标签不关闭同级标签 |
| FR-10 | Runtime 共用生产入口 | 直连模型和现有 MCP 网关使用同一 BrowserService；模型选择、启用设置和请求归属保持一致 |

## 场景验收

- US-1（FR-1、2、3）：AI 读取页面、填写中文、操作 iframe 并点击长页面下方按钮。用户看到原有网页界面和真实结果。
- US-2（FR-4、5）：在系统 100% 与 150% 缩放下直接输入中文、复制粘贴并调整面板尺寸；AI 随后读取和修改同一字段，无需额外按钮。
- US-3（FR-6）：用户点击网页文件字段，或 AI 使用文件字段工具上传；网页下载保存在下载目录，关闭标签后仍存在。
- US-4（FR-7、9）：点击开窗链接后模型绑定新页；关闭该页不影响原页；取消等待中的点击后再启用按钮，不能发生迟到点击。
- US-5（FR-10）：现有 MCP 请求能发现并执行升级后的工具；Linux Host 通过桌面网关验证新工具协议。该测试与新增远端独立浏览器部署分别记录。

## 验证边界

目标平台继续为 Windows、macOS、Linux x64 和 Linux arm64，实际完成的平台与缩放场景以实施记录为准。此次不扩展远端 Agent 的浏览器部署范围，不承诺绕过网站验证码、硬件认证或网站自身限制。
