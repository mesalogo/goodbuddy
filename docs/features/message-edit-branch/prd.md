# 产品需求

用户需要修正较早的要求或尝试不同表达，同时保留原讨论作为参考。

## 功能要求

- FR-1：桌面用户可编辑任意一条已发送的用户消息，包括本机和托管 SSH 项目。外部消息通道的只读会话不提供此入口。
- FR-2：保存后建立新分支，包含历史前缀、修改后的用户请求和新回复。原消息及其后续讨论保持原样；不自动重放后续问题。
- FR-3：原附件默认保留，允许移除；通过现有附件能力补充或替换附件。缺失资源须明确报错，不得静默省略。
- FR-4：自动切换至新分支并发起一次回复。保留来源信息和返回原会话入口。
- FR-5：编辑草稿独立于普通输入草稿。取消不创建分支；提交失败保留输入；生成失败沿用队列及回复重试能力，不能迫使用户重新输入。
- FR-6：源会话执行中或存在待发送内容时，说明暂不能提交的原因。重复点击只创建一个分支、发送一次。
- FR-7：新回复使用当前会话选择的 Runtime、模型、角色和知识库，清除原会话的压缩状态及运行上下文。项目记忆和实际工作区仍按当前状态工作。
- FR-8：附件及历史工具全文在分支和重启后仍可访问。复制的历史前缀不重复作为监督回顾的新证据。

## 产品边界

本功能不撤销已执行的文件或外部操作，不实现工作区时间旅行，不提供会话内消息树导航。历史回复中的任务与图片操作仅供查阅，不应被复制为可继续执行的旧任务。

验收以真实界面操作经 Preload、Main、存储和 Runtime 形成新回复为准；自动测试覆盖范围见用户故事和技术设计。
