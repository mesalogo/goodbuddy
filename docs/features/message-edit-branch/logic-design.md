# 行为规则

## 分叉不变量（FR-1、FR-2、US-1、US-9）

存储层确认编辑点属于指定源会话，且 role=user；按 sequence 复制严格位于编辑点之前的消息。复制消息生成新 ID，源记录不更新。修改后的请求通过现有发送队列进入新会话。

## 编辑及失败状态（FR-5、FR-6、US-3 至 US-5）

阅读 → 编辑 → 提交 → 新分支。取消编辑回到阅读，不写存储。空白或超长文本无法提交；提交期间禁止重复点击。源会话忙碌时保留编辑内容，提交前由 Main 和存储再次检查。

存储失败保留编辑器；分支创建后先登记到会话 store，再调用发送队列，保证 dispatch 能找到目的会话。队列接收失败保留新分支及可恢复草稿；已接收请求不自动再次发送。生成失败和取消使用现有回复状态和队列恢复机制。

## 上下文与资源（FR-3、FR-7、FR-8、US-2、US-6 至 US-8）

新会话不继承压缩摘要、token 指标或原生 Runtime 会话。知识库、角色及故事图谱启用设置沿用源会话当前选择。所有模型只接收历史前缀和新请求。

引用复用实际资源；新分支建立自己的引用。复制消息标记原始来源，监督回顾排除复制记录。原分支的项目记忆仍可被检索，来源会话保持可追溯；分叉不宣称撤销项目已发生的事实。

逻辑完整性：正常、取消、重复提交、源忙碌、资源缺失、创建失败、发送失败、生成失败及来源删除均有明确结果。外部通道继续只读。
