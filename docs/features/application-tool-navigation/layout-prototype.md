# 经典与工作台布局原型

本页记录 2026-10-25 的候选布局及原型边界，供正式接入前评审。入口为
[四栏 Demo](./four-column-demo.html)。正式产品仍使用既有布局；本文不替代已经实现的功能规则。

## 名称与入口

建议在现有“设置 → 外观”中增加“界面布局”，使用两张带结构示意图的单选卡片。
沿用现有外观选择控件和主题令牌，设置页面本身不改版。

| 选项 | 说明 | 结构 |
| --- | --- | --- |
| 经典布局 | 应用入口与会话列表集中在左侧，沿用熟悉的界面。 | 综合侧栏、聊天、工作区 |
| 工作台布局 | 独立应用导航，会话列表可收起，聊天与工具工作区并列展开。 | 应用导航、项目会话、聊天、工作区 |

四栏是工作台展开后的状态。顶部“专注 / 聊天 / 工作”仅为 Demo 的收放预设，与布局类型分开。
Demo 右上角“外观设置”和左下角账户菜单均可打开同一个选择框。选择立即生效，设置框保持打开；关闭后可查看完整界面。

## 候选行为

- 正式产品首次引入时，已有用户保留经典布局。Demo 为便于评审，未保存偏好时默认展示工作台。
- 两种布局分别记住项目会话栏的展开状态、工作区展开状态和聊天分栏比例。正式接入还应分别记住左栏宽度。
- 切换时共享当前项目、会话、草稿及工作区标签；切换布局不重建聊天、编辑器、终端或浏览器实例，不中断执行。
- 深浅主题独立于布局选择，两种布局均支持。正式产品沿用现有主题持久化；本 Demo 的主题仅保留到刷新前。
- 窗口变窄自动隐藏项目会话栏，用户可重新展开抽屉；自动隐藏不写回宽窗口偏好。恢复宽窗口时读取原偏好。
- 最大化是临时状态，切换布局退出最大化。各布局保存的工作区展开状态继续恢复。

正式产品的当前客户端偏好可沿用已有本地界面偏好机制。会话与工具数据使用已有权威来源，避免为两种布局各保存一份内容。

## 原型实现范围

HTML、CSS 和 JS 仍使用 `four-column-demo` 文件名。两种布局移动同一组导航节点，聊天及工作区 DOM 保持原位；经典侧栏内显示导航文字，工作台使用独立图标栏。共享消息、草稿和标签只在当前页面内存中保存。

Demo 在浏览器 localStorage 的 `goodbuddy.demo.four-column-layout.v1` 中保存布局类型、各布局收放状态和聊天比例，刷新后恢复；该键与产品偏好隔离。浏览器禁用存储时，本次页面内仍可切换。“恢复初始布局”重置这组偏好并恢复浅色，不清除当前消息或标签。

Demo 的经典模式仅比较入口组织和空间关系，项目树等演示内容沿用原型；并非现有客户端逐项复刻。示例文件、浏览器与终端不连接真实服务。布局切换保留当前工作区内容，但原型原有的标签切换仍会重新绘制示例内容，不能用它证明真实编辑器的状态保留。

## 正式接入边界

### 主题与视觉方案补充

2026-10-25 的后续讨论将新版范围扩展到页面内容与共享组件。布局定义区域组织，视觉方案定义背景、文字、边框、间距和控件层级，亮色／暗色是视觉方案的两种表现。它们在代码中分开维护；设置不必暴露全部组合。

当前候选方向是：验证阶段保留经典界面的熟悉体验，工作台采用新的视觉方案，亮暗模式共同设计。经典是否最终同步新配色、工作台的具体色值、是否提供“跟随系统”，仍需原型验证与产品确认；不据此更改现有用户默认值，也不承诺长期维护两套业务页面。原先讨论过的“经典与工作台立即统一升级配色”不作为本阶段实施结论。

现有 Demo 不等于全新主题已完成：四栏 Demo 的经典模式是结构示例；多页面 Demo 仍引用产品基础令牌。后续应检查主内容、导航、列表、浮层、表单、代码与状态色在亮暗模式中的一致性。暗色单独调整对比与表面层级，避免机械反色；品牌强调色是否更换由视觉评审确定。

组件与目录维护计划见[页面内容检查](./page-content-review.md#组件规范与维护计划)。本轮只补充文档，现行产品继续遵循根目录设计系统；候选规则正式接入时同步更新权威规范。

### 组件与生产接入

现有 `styles.css` 已拆分基础、应用外壳、聊天、工作栏和设置样式。正式接入应复用基础令牌、共享控件和内容样式，将经典与工作台的排列、尺寸、分隔规则限定在布局属性下。需一起检查全局深色覆盖与响应式规则，避免旧选择器覆盖新布局。

`App.tsx` 当前将导航、会话列表和底部入口放在同一个侧栏中，需要抽出可共享的导航视图与布局壳。布局状态遵循[性能原则](../../architecture/performance-principles.md)的局部订阅约定，不继续向 App 增加领域状态。右侧工作栏已有标签与比例持久化，可在原模块中扩展布局偏好，保持内容实例身份。

正式页面遵循[统一界面设计系统](../../../UI-DESIGN.md)。笔记、知识库已有内部列表，接入时需确定第二栏的归属，避免重复侧栏；这些完整应用页面未在本原型中设计。窗口拖拽区域、系统窗口按钮、磨砂顶栏、菜单锚点及键盘焦点需要真实 Electron 验证。

## 评审与验收场景

| 操作 | 预期 |
| --- | --- |
| 输入草稿、打开文件后往返切换布局 | 草稿、标签和当前文档仍在 |
| 分别调整两种布局的收放与比例，再切回 | 各自恢复原选择 |
| 保持设置打开，连续切换单选项 | 即时更新底层布局，设置框不关闭 |
| 重新加载 Demo | 布局偏好恢复；消息与示例标签恢复初始内容 |
| 缩窄窗口后再放宽 | 项目栏临时隐藏，恢复原展开偏好 |
| 经典模式收起侧栏 | 顶部仍可打开外观设置并切回 |
| 浅深主题及键盘操作 | 卡片、选中态和焦点可辨，分隔线支持方向键 |

原型验证事实与剩余工作统一记录在[实施进度](./progress.md)。正式实施时再将批准的行为分配到 PRD、逻辑、UI 和技术设计，并建立正式需求编号。
