## 1. 定义

页面级应用是从左侧应用导航进入、占据整个内容区的独立页面。它有自己的标题、对象列表和内容，不依附于当前会话。

在工作台布局下：

- 进入页面级应用时，会话列表让出第二栏；返回对话时恢复。会话列表只是隐藏，保持挂载，用户的展开偏好不变。
- 对话页的顶栏（侧栏开关、会话标题）只属于对话，页面级应用不显示。页面从内容卡片顶部开始。
- 右侧工作栏仍可打开，页面按剩余宽度适配。

经典布局保持现状：会话列表在所有页面常驻，页面放在外边距和卡片中。

弹窗类入口（设置、应用中心、本机推理监控）不属于页面级应用，它们覆盖在当前页面上，关闭后回到原处。

## 2. 页面类型

每个页面级应用归入下面两类之一，不混用。

| 类型 | 适用条件 | 工作台布局下的结构 | 页面 |
|---|---|---|---|
| 列表 + 详情 | 页面管理一组同类对象，用户先选对象再处理 | 第二栏是对象列表，标题和主要操作放在栏顶；详情区占满其余空间 | 魔法笔记、知识库 |
| 单栏 | 没有需要常驻的对象列表，或对象数量少、以概览为主 | 页面标题和页签在顶部，内容占满宽度，按内容类型限制阅读宽度 | 监督者、主机管理、设备共享、运行记录 |

监督者的“图谱”页签内部有“列表 / 画布 / 详情”三栏，这是页签内容，不升级为页面第二栏：监督者的主要对象是回顾与计划，图谱只是其中一个视图。

## 3. 结构约定

### 3.1 外壳与容器

```text
KeepAliveRoute(route)          保活、未保存修改上报
└─ RouteErrorBoundary + Suspense
   └─ PageShell(variant)       唯一的页面滚动容器，命名容器 page-shell
      └─ 页面根元素            页面自己的网格；需要时声明自己的命名容器
         ├─ PageHeader
         ├─ PageTabs（可选）
         └─ 内容
```

- **PageShell 由 App.tsx 包裹**，页面组件不自己渲染 PageShell。这样外壳、保活和错误边界在一个位置维护。
- 所有 `page-shell--*` 变体都是命名容器 `page-shell`。页面内的响应式规则按实际可用宽度判断（会话列表、工作栏都会占用窗口宽度），不用 `@media` 判断窗口宽度。
- 容器查询必须写名字。不带名字的 `@container` 会匹配最近的任意容器，页面里一旦嵌套了别的容器，判断对象就变了。
- 容器不能查询自己的宽度。要按宽度改变网格的元素，必须由它的祖先提供容器。知识库的做法：`.knowledge-page` 提供 `knowledge-page`，列表和详情的网格由它决定；详情区 `.knowledge-workspace__main` 再提供 `knowledge-main`，详情内部按详情区宽度判断。

### 3.2 PageShell 变体

| 变体 | 内容宽度 | 用于 |
|---|---|---|
| `master-detail` | 占满，四周统一边距；工作台下边距为 0，列表贴边 | 列表 + 详情页面 |
| `standard` | 居中，最大 960px | 表单、卡片列表为主的单栏页面 |
| `dashboard` | 居中，最大 1040px | 统计、表格为主的单栏页面 |
| `supervisor` | 居中，最大 1440px | 需要宽画布的单栏页面 |
| `reading` | 对话专用 | 对话 |

### 3.3 PageHeader

| 属性 | 规则 |
|---|---|
| `icon` | 必填，使用与左侧导航相同的图标，尺寸 20 |
| `title` | 与左侧导航名称一致 |
| `description` / `help` | 二选一。说明需要常驻可见时用 `description`；页面已有足够上下文、说明只在需要时查看时用 `help`。现有页面（魔法笔记、监督者、运行记录用 `help`）保持不变，不为统一而改 |
| `scope` | 必填，说明数据范围：全局、当前项目或全部项目 |
| `actions` | 页面级操作（新建、刷新、管理），最多一个主按钮 |

工作台布局下，列表 + 详情页面的 PageHeader 放在第二栏顶部：只显示图标、标题和范围；说明文字隐藏（空状态中会出现）；操作排成一行，主按钮占满，次要操作收成带提示的图标按钮。

### 3.4 滚动

- 每个区域只有一个纵向滚动条。
- 列表 + 详情页面在双栏时，列表和详情各自滚动，PageShell 不滚动；收成单栏后，内部滚动关闭，由 PageShell 滚动。
- 依赖滚动容器的逻辑（虚拟列表、滚动位置恢复）要先找实际在滚动的元素，不能写死 `.workspace-panel-scroll`。

### 3.5 窄宽度

列表 + 详情页面在页面宽度不足 780px 时收成单栏：默认显示详情，通过“返回列表”切换到列表。标题和操作恢复为同一行。

公共修复：

- 所有 PageShell 变体都是命名容器 `page-shell`。此前 `standard` 不是容器，主机管理和设备共享里按宽度判断的规则、以及共享的 PageHeader 换行规则从未生效。
- 窗口在 900–1020px 时，收起的会话栏仍占 278px 宽度（经典布局同样受影响）。
- App.tsx 新增 `LazyRoute`（错误边界 + 加载占位），六个页面统一使用。设置是弹窗，加载时不显示占位，保留原写法。
- 项目恢复状态的旋转图标原来借用主机对话框的动画，主机样式按需加载后会失效；改为独立的 `project-recovery-spin`。

## 5. 后续

无必须项。可选：

- 魔法笔记的列表宽度与抽屉阈值（600px）和页面双栏阈值（780px）分别定义在 JS 与 CSS 中，以后调整时需同时修改。

每次调整页面级应用的验收：工作台与经典布局各自截图（宽屏、工作栏展开、窄窗口、暗色）；切换页面后会话列表的展开偏好和对话草稿保留；相关测试通过。
