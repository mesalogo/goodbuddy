## 统一设计方向

主内容使用连续画布。页头集中显示范围、当前对象和主操作，页签只切换同级视图。筛选放在所属列表上方，表格利用可用宽度，正文限制阅读宽度。状态以文字加颜色表达，错误留在能够恢复的位置。

卡片适用于笔记总览、应用目录等独立对象。连续记录、服务行和参数分组优先使用细线和留白，避免为每层容器增加背景与边框。说明、时间和主内容分级，但保持可读字号与对比度。

Demo 提供舒展／紧凑间距，用于比较行高和页面留白，尚未决定增加产品设置项。深浅主题读取产品的基础 CSS 令牌；字体使用基础令牌及系统回退，不请求远程字体。正式接入继续使用客户端已打包的字体。

响应式应按实际内容容器判断。原型在窄窗口隐藏对象导航，并在主区保留必要入口；阅读辅助区改为下方内容。聊天工具区在窄容器下上下排列仅供样式评审，正式采用抽屉、单面板切换或其他行为仍须结合[布局原型](./layout-prototype.md)统一决定。

## 组件规范与维护计划

2026-10-25 补充：新版评审范围包括布局、亮暗主题、共享组件和页面内容。当前先更新设计文档；下列目录、组件整理与验收安排属于后续计划，本轮不迁移生产代码、不新增 `AGENTS.md`。

### 职责与目录

正式接入应先盘点现有实现，按职责整理，复用已有组件与令牌。目录按实际迁移内容逐步建立，不预建空目录，不复制整套经典与工作台业务页面。

| 职责 | 现有基础与候选归属 | 维护边界 |
| --- | --- | --- |
| 应用外壳 | 现有 App 与外壳样式；候选 `app-layout/` | 导航组合、分栏、栏宽和收放；经典与工作台差异放在子目录 |
| 主题 | 现有基础令牌；候选 `theme/` | 亮暗配色及视觉变量；业务页面通过语义令牌使用颜色 |
| 通用控件与页面结构 | 现有 `WorkspacePrimitives.tsx` 等；候选 `ui/` | 按钮、表单、页签、页头等公共表达，不持有项目、会话或工具实例 |
| 业务内容 | 现有各功能模块 | 笔记记录、知识文档、工具调用等业务结构，复用公共控件 |
| 原型 | 当前文档中的 Demo 目录 | 示例数据和评审交互，与生产状态、持久化分开 |

迁移前记录源文件、目标位置、使用方和关联测试；迁移时更新引用及样式入口，并移除同范围旧规则。临时兼容导出必须记录剩余使用方和移除条件，避免长期存在两个维护来源。已有共享 CSS 足够表达的控件，不强制增加只有透传属性的 React 包装。

### 组件盘点与优先顺序

逐项记录“现有实现、使用页面、重复实现、处理方式、验证缺口”。处理方式区分继续复用、扩展现有组件、合并重复实现和保留业务专属组件。此前页面检查只确认了代表性结构，尚未完成全量组件盘点。

| 优先范围 | 规范内容 |
| --- | --- |
| 按钮、图标按钮、输入与选择控件 | 主次操作、尺寸、标签、聚焦、禁用、加载与错误状态 |
| 页签、分段控件、开关 | 沿用现有共享实现与语义，明确导航、视图选择和持久状态的区别 |
| 菜单、帮助、弹窗与通知 | 复用现有浮层和焦点机制，检查 Escape、焦点返回、滚动及原生浏览器遮挡 |
| 页头、工具栏、表单分组 | 标题和范围、主操作、说明、字段校验与窄容器排列 |
| 列表行、状态、空态与详情 | 信息优先级、行内操作、长文本、无结果及就地恢复 |
| 分栏及业务内容 | 尺寸边界、键盘调宽、连续阅读、表格和独立滚动 |

共享组件的使用说明至少包括用途、适用范围、已支持的变体、交互状态、键盘行为和代表使用方。属性表达明确语义，避免不断叠加页面名称或布尔开关。单一页面中的不稳定结构先留在功能模块，等出现相同需求后再抽取。

基础控件通过主题变量适配视觉；只有导航组合等结构差异需要识别布局类型。不要向每个按钮、输入框传递 `classic` 或 `workbench`，也不要让共享控件依赖业务页面或 `App.tsx`。

### 组件语义与用户预期

组件规范同时约定用户含义、交互结果和辅助技术语义。外观相近不代表用途相同；同一含义在不同页面应采用一致的控件、名称与反馈。评审时先确定操作含义，再选择组件，不能仅凭截图相似套用样式。具体交互继续遵循[统一界面设计系统](../../../UI-DESIGN.md#6-共享组件)。

| 用户意图 | 控件与语义 | 容易混淆的用法 |
| --- | --- | --- |
| 进入功能或对象 | 导航入口，清楚标识当前位置 | 将一级功能入口做成表单选项；当前项与悬停项无法区分 |
| 查看同一对象的同级内容 | PageTabs，关联对应内容面板 | 点击页签实际启用服务、修改配置或执行命令 |
| 改变当前内容的显示方式 | SegmentedControl，表达互斥视图选择 | 用相同外观混合页面跳转、筛选和即时操作 |
| 缩小当前数据集合 | 搜索与筛选，显示当前条件并允许清除 | 将筛选无结果显示成首次使用的空状态 |
| 立即切换持续生效的二元状态 | Switch，名称描述被控制的能力 | 开关看似已生效，实际还需点击远处的保存按钮 |
| 勾选对象、分配范围或确认事项 | Checkbox，表达独立选择 | 用滑动开关表示批量勾选或一次性确认 |
| 选择互斥配置值 | Radio 或单选选择器，明确当前值 | 多选外观用于单选；仅打开配置流程就显示为已选中 |
| 执行操作 | Button，名称说明动作及必要对象 | 用“确定”“处理”等含糊文案掩盖保存、删除或连接行为 |
| 展开细节或菜单 | 展开按钮，标识展开状态与受控内容 | 箭头看似展开详情，点击却离开页面或改变启用状态 |
| 展示状态、范围或数量 | 标签、徽标与文字，默认只读 | 只读标签看起来可点击；用颜色或图标单独表达关键状态 |

若二元值需要随整张表单提交，应按现有表单语义表达，并明确“保存后生效”；不能仅为统一外观套用立即生效的 Switch。带分段外观的页签仍保留页签语义，视觉变体不改变其行为。

每个共享组件的说明需写清：用户正在选择、导航、展开还是执行；操作是否立即生效；影响哪个对象或范围；等待、成功与失败如何呈现。纯展示组件也要说明是否允许交互。业务页面负责提供准确的动作名称和作用对象，基础组件负责稳定的行为与可访问语义。

图标按钮必须有可访问名称和可发现的文字提示。删除、断开连接、停止执行、关闭标签、隐藏面板分别表达不同后果，不能共用含糊的“关闭”名称。选中、启用、连接中、执行中和不可用也应分别呈现；常驻导航不等于启用应用，隐藏面板不等于停止后台任务。

语义验收使用具体场景：仅看控件名称与当前状态，是否能判断作用对象和操作结果；执行后的变化是否符合预期；键盘及屏幕阅读器得到的角色、名称和状态是否与可见界面一致。组件展示入口应并列演示易混淆的控件，评审人员逐项检查名称与实际行为，不能只检查颜色和尺寸。

### 状态与样式维护

布局切换只调整视图组织，业务数据继续使用已有权威来源。聊天、编辑器、终端和浏览器保留稳定实例；不能通过两个完整应用分支切换来实现布局。隐藏视图的资源与订阅按现有生命周期管理，不以永久挂载所有页面代替状态设计。

布局偏好和领域状态遵循[性能原则](../../architecture/performance-principles.md)的局部订阅要求。草稿、阅读位置、工作区实例与布局宽度分别归属原有业务模块或布局模块，不为两套界面复制状态，也不继续向 App 增加领域逻辑。

公共控件样式与业务排列分开维护；页面样式使用功能范围选择器，布局差异限定在布局根属性下。主题取值集中维护，Portal 和原生 top layer 中的菜单、弹窗也须取得当前主题。新增规则前检查已有深色覆盖和响应式规则，避免靠提高选择器权重或追加 `!important` 修补冲突。

### 示例与验证

后续 Demo 增加组件展示入口，集中比较亮暗模式、常用状态和窄容器表现。当前多页面 Demo 尚无该入口。正式迁移后，组件展示应引用真实共享组件，静态 HTML 只作为候选外观参考，避免两份展示长期分化。

每批迁移选择有代表性的真实页面验收，并按实际影响检查：

- 默认、选中、悬停、键盘聚焦，以及适用的加载、禁用和失败状态。
- 亮暗主题、长名称、中英文、窄聊天窗格、短窗口与内部滚动。
- 切换布局后的草稿、阅读位置和工具实例；运行中任务继续使用原执行路径。
- 浮层的焦点恢复、Escape 层级和 Electron 原生浏览器相交行为。

验证命令与结果记入所属功能进度。公共组件行为变更覆盖代表使用方；纯文档更新只检查文档。截图不能替代交互测试，组件夹具不能证明生产 IPC 或真实工具生命周期已通过。涉及热点路径时按性能原则提供测量。

## Demo 目录与维护

```text
page-design-demo/
  index.html   # 外壳、全局入口、共享弹窗
  shared.css   # 页面标题、列表、表格、按钮、状态和表单
  pages.css    # 聊天、笔记、图谱及弹窗内容的专属排列
  pages.js     # 各页面示例内容与渲染函数
  app.js       # 页面导航、演示状态与交互
```

本原型与四栏布局 Demo 分开，互相提供入口。公共结构和页面样式已有独立文件；产品接入时应迁入既有共享组件与各功能目录，布局选择继续归属 `app-layout/` 的候选职责。无需把笔记、知识库等业务内容搬到布局目录，也不引入另一套业务数据和公共控件。

`index.html` 相对引用仓库里的基础样式，直接从本地打开可用；HTTP 预览应以仓库根目录作为服务根，否则基础样式 URL 不可达。

## 交互与限制

页面导航保留已打开页面的 DOM、草稿及滚动位置。示例消息、笔记记录、待办、主机及开关在当前页面内存中变化，刷新后恢复。没有真实 API、模型、文件、凭据或远程主机访问。

设置、应用中心和推理监控仍以 Modal 打开，关闭回到底层页面。原生 dialog 提供模态背景隔离；页签支持左右方向键与 Home／End，单选使用原生 Radio，持久二值状态使用 Switch 语义。复杂表单的未保存确认及真实执行状态尚未实现，原型不能作为其验收证据。

知识库失败详情、搜索无结果、处理中和资源未知状态有代表样例。加载中、权限不足、长列表窗口化、运行中切换、所有错误恢复与跨平台窗口行为仍需在正式组件上验证。

具体执行的检查结果见[实施进度](./progress.md)。正式产品改版前，应将批准的页面调整分别写入所属功能的 UI／逻辑设计；本页只维护本轮跨页面评审记录与原型范围。
