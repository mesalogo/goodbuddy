# 文档处理

文档处理负责聊天附件和知识库导入中的文本提取、本地 OCR、HTTP PaddleOCR-VL、原件与
解析产物保存，以及正文、图片、详情预览。格式转换仍为规划能力。
2026-09-19 已接入生产链路；验证层次、样例和未覆盖项见[实施进度](./progress.md#2026-09-19-实现与验证)。

User Stories、逻辑设计和进度文档覆盖 HTTP OCR 扩展、纯图片路由及资源持久化，本地 OCR
既有实现仍由 PRD 及聊天附件技术说明维护。界面行为由 UI 设计维护并遵循根目录
[UI 设计系统](../../../UI-DESIGN.md)。完整目标包含文档选图加入会话并发送，不以实施顺序
缩减产品范围。具体生产实现和验证证据分别由实施说明与进度文档维护。

全局配置、本机推理监控、聊天附件和知识文档的入口分工，以及草稿、历史与队列的菜单规则，
统一见 [入口与职责](./ui-design.md#11-入口与职责)和[附件操作菜单](./ui-design.md#12-附件操作菜单)。
首次菜单核对保留在[历史记录](./progress.md#菜单核对)，当前接线见生产实现说明。

本文档中的“内联图片”指服务在 JSON 中返回的 Base64 图片字节；“图片键”指
Markdown 引用及 `markdown.images` 中的页内键，不是可直接写入磁盘的路径；“重组”指
对已解析页面调用 `/restructure-pages`，不等于已经验证跨页表格合并质量。
“会话资源”是应用 userData 下的文件资产及数据库归属引用，不是 Runtime 项目文件；
服务返回“内联图片”也不表示产品将图片字节长期存入数据库。

“待添加选择”仅指预览内尚未提交的勾选；“已在草稿”指目标会话实际持有的附件引用。
“文档插图附件”是显式复制到会话资源目录的独立图片，保留来源说明，不依赖知识库原结果
继续存在。“提取文字”是图片附件的一种发送方式，原图仍保留，不表示原图同时发给模型。

“纯图片附件”指直接添加到聊天的图片，与 PDF、Office 解析提取的“文档插图”分开。
普通图片默认直接作为模型图片输入，明确提取文字才调用配置的 OCR；不支持图片输入时的
提示和选择、原图长期保存见 [图片路由](./prd.md#322-纯图片与文档的路由规划)；验证范围见进度。
约定的 userData 目录、既有 knowledge 原件与规划派生资源的区别统一见
[结果与资源](./http-paddleocr-vl-technical-design.md#结果与资源)。

Office 文件的浏览器内人工编辑、AI 选区修改、保存和撤销不属于文档解析职责，由
[Office 协同编辑](../office-document-editing/README.md)负责。文档处理仍负责内容提取、OCR、
旧格式转换和供模型消费的统一结构。
