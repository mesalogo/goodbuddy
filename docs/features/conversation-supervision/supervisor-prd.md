# 监督者应用产品设计

日期：2026-09-16。状态：目标设计已确认，尚未接入产品。

本文定义监督者应用的定位、功能边界与知识库关系。[会话监督 PRD](./prd.md)继续负责对执行过程的观察、证据与介入边界；本文将该能力纳入更完整的工作回顾应用。

## 产品定位

监督者是持续关注指定工作范围的智能 Agent。用户可以主动要求回顾，也可以通过智能心跳定期唤醒它。它根据可见记录判断是否需要反馈、整理阶段或更新知识关联，没有值得反馈的变化时保持安静。

| 名称 | 职责 |
| --- | --- |
| 监督者 | 应用名称，负责观察、回顾和解释工作进展 |
| 智能心跳 | 按计划唤醒监督者的机制，保留计划与运行管理 |
| 监督反馈 | 会话右侧的阶段回顾、问题提示与证据入口 |
| 故事线图谱（Story Graph） | 呈现事件、知识实体及其随时间发展的关系 |

FR-S1：将现有智能心跳入口整合、升级为监督者，不增加另一个平级重复应用。当前通过应用中心管理；未来应用市场提供同一应用的发现与启用入口。市场建设不应成为监督者落地的前置条件。

FR-S2：应用包含“工作回顾”和“故事线图谱”两个主视图。设置管理关注范围、心跳计划、整理时机和反馈方式。原有计划、运行记录及用户启用、常驻偏好应保留；具体标识映射与数据迁移由后续技术设计确定，本轮不更名生产页面或存储字段。

## 范围与触发

FR-S3：首次启用时选择项目、会话及可用来源，生成前显示范围和时间区间。应用启用不等于默认观察全部内容。已有心跳的 Global、单项目和多项目范围语义由[智能心跳 PRD](../smart-heartbeat/prd.md)定义，统一应用时保留。

FR-S4：支持手动回顾，并复用已有定时检查机制。每次整理只处理所选范围内的有界输入；无新增有效信息时不重复发送反馈。事件触发、阶段自动判定和增量整理策略尚待设计，不因 Agent 定位而默认获得工具执行能力。

FR-S5：会话右侧在跟随模式下展示当前会话的监督反馈；固定到 Conversation、Task 或 Experiment 时保持所选目标并显示其名称，切换聊天不改变监督目标。跨会话总结在完整应用中展示。反馈包含结论、来源和“在图谱中查看”定位入口。用户主动选择“发到当前会话”才加入聊天消息，同一结果不重复触发侧栏和全局通知。

FR-S6：监督者可提出整理与修改建议；已有会话监督的观察边界继续生效。自动更新图谱不能静默覆盖用户修改的描述、已确认的关系或已有知识库正文。取消整理后保留上次结果；失败说明受影响范围并允许重试，部分结果不得显示为完整回顾。

## 与知识库的关系

FR-S7：知识库管理资料、索引、检索和可复用知识；监督者管理工作事件、阶段总结与演变关系。故事线图谱共用现有来源，引用知识库对象，不复制一套资料正文，也不取代已有知识库图谱。

一个知识实体可以关联多份资料，一份资料也可支撑多个实体。图谱的关系与阶段记录由监督者维护，原始内容由所属会话、笔记或知识库维护。新增功能的概念实体与现有图谱实体是否共用标识，需结合现有模型制定技术方案。

FR-S8：本地知识库提供双向定位：资料详情可进入相关故事线图谱，图谱详情可返回资料及引用位置。已有本地条目显示“打开知识库条目”；新归纳提供“新建条目”或“补充已有条目”，先预览内容和引用再保存。外部引用沿用现有能力，打开已保存的有界片段及可用定位信息，不承诺重新打开远端原文；缺少位置时明确提示。外部知识库保持只读；不得因图谱整合而增加对 Dify、FastGPT、RAGFlow 的写入或批量同步。

FR-S9：来源事实、自动归纳、待核对关联和用户确认内容分别标注。移除关联不删除原文，纠正操作可撤销。来源失效时显示不可用状态；回放历史时使用当时已有的归纳与依据，无法恢复旧版原文时明确提示，不能以当前版本冒充历史内容。

## 落地范围

触发、整理与结果共享规则，以及整体架构和图谱对象关系见[逻辑设计](./logic-design.md)。

首个完整流程为：启用监督者、选择范围、生成回顾、进入图谱、核对来源、携带选定上下文继续讨论。知识库双向定位与内容补充随后接入同一流程。图谱关系辅助检索需单独验证效果，不作为首版默认检索策略。

当前智能心跳已有计划和手动运行能力；会话监督仍在设计中；故事线图谱只有模拟数据 Demo；应用市场尚未实现。本文不构成这些目标能力已交付的证据。

具体 UI 与验收见[UI 设计](./ui-design.md)和[User Stories](./user-stories.md)。图谱对象与操作由[故事线图谱设计](../story-graph/prd.md)定义。技术设计仍需确定实体标识、来源定位、历史版本能力、计划兼容及增量整理方式。
