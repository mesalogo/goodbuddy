# 监督者 UI 设计

日期：2026-09-16。状态：目标设计，遵循根目录 [UI-DESIGN.md](../../../UI-DESIGN.md)。需求对应[监督者应用产品设计](./supervisor-prd.md) FR-S1 至 FR-S9。

## 应用入口

应用中心中的智能心跳入口升级为“监督者”，沿用既有启用、常驻与排序能力。未来应用市场使用同一应用身份。应用已启用时，停用单条自动心跳计划仍可手动回顾；关闭应用后，已打开页面显示关闭状态并禁用工作区操作。默认值及运行边界见[应用启停与执行](./logic-design.md#应用启停与执行)。

当前应用页只使用一套共享 PageTabs：“工作回顾 / 故事线图谱 / 自动监督 / 活动记录 / 设置”（英文活动标签为 Activity records）。自动监督独立管理计划；设置只显示模型超时与并发、回顾算法，不含计划、报告、审计或内部页签，也不显示整页全局徽标或独立刷新行。计划范围仍在表单和每条计划内显示。整个页面只有一个一级标题；监督者 bridge 不可用时显示明确错误，设置仍可访问，不回退到旧心跳概览。共享页签保留方向键、Home/End、游标焦点和单一激活面板，窄窗口横向滚动。

工作回顾只读取统一监督结果。顶部为紧凑的“新回顾”范围、时间、发起与刷新控件，不新增 Modal；简短帮助说明选择仅作用于新请求。历史结果选择与图谱入口位于正文之前，即使只有一条结果也显示选择器。新回顾工具栏、状态、历史选择和结果面板铺满监督者页面壳层的可用内容宽度，与页签左右对齐，不另设阅读宽度上限；结果内部按面板内边距排版，不再单独居中窄正文。正文使用“监督结果”标题，常显生成日期、真实范围和覆盖区间，历史结果不标为最新。工作总结按原有空行分段并保留换行；本次变化和未解决事项直接使用已有字段，不补写结论或截断正文。390px 下新请求字段与操作各占两列，结果元数据可换行。

新回顾运行中保留已显示结果及其日期、范围，禁用重复提交，并显示简短状态和活动记录入口；该入口清除计划筛选并聚焦活动页签。工作回顾不读取自动监督报告，也不显示自动报告空态、记忆与行动建议或第二行全局范围与刷新。无监督结果时显示手动回顾入口；自动报告是否为空不影响此判断。

## 活动

文案遵循根目录 [监督者文案规则](../../../UI-DESIGN.md#134-智能心跳)：不把内部路线图、交付状态或实现缺项展示给用户。活动说明只描述手动回顾、自动监督执行及自动刷新；真实错误、失败和暂停状态仍展示，并保留恢复操作。事实详情提示展开批次并对照原文核对模型内容，不承诺完整语义识别；图谱说明实体状态以所选回顾结果为准。

对应 FR-S10、US-S26。活动按开始时间倒序，每页 50 条，提供较新/更早记录和刷新。列表保留触发方式、执行范围、开始/结束时间、实际状态、阶段状态、错误及已保存摘要。没有结果时不显示结果按钮；有监督结果时可分别进入该结果的工作回顾和故事线图谱，焦点移到目标页签。超过最近 20 条的结果仍按 ID 读取，不能回退最新结果。

活动页只展示统一监督活动、进度、详情及结果入口，不在列表下方重复显示自动监督概览或心跳审计。计划“执行记录”打开此页并按精确 ID 筛选，筛选器显示所选计划并提供清除；监督查询在分页前过滤。同名计划仍按 ID 区分；没有匹配记录时显示筛选无结果，不回退全部数据。自动报告正文和建议处理位于自动监督。

自动监督页依次展示范围与“刷新自动监督”、当前状态及计划列表、运行指标、报告趋势、待确认记忆与行动建议、“自动监督报告”历史、心跳报告阶段审计。刷新统一更新此页数据。报告与运行历史每次追加 20 条，报告可展开全部摘要和洞察，切换页签保留展开与分页位置；不再单独复制最近报告。建议保留确认、忽略、带入对话、标记完成及长内容展开。活动的计划筛选不改变自动监督的统计范围。当前状态下复用计划列表的唯一创建按钮，无计划时只显示列表的未配置说明，不叠加第二个计划空态或创建入口；点击直接打开现有 Modal。报告为空时明确写“暂无自动监督报告”，与工作回顾的结果状态区分。

加载、空记录和读取失败分开显示；读取失败保留已显示记录并提供就地重试。活动页面激活时，存在运行中记录则在上次读取结束 2 秒后刷新，否则 10 秒后刷新；每次最多一个请求。切换顶层页签、离开监督者或关闭应用后停止定时器，迟到响应不更新界面。错误后等待用户重试，不持续重发失败查询。

活动列表与工具栏铺满监督者页面壳层的可用内容宽度，与页签左右对齐，不另设仪表盘宽度上限。范围、计划筛选、清除筛选和刷新紧邻排列，空间不足时换行。列表使用共享表面、边框、状态颜色和按钮。每条运行首先显示类型、状态、开始时间和范围；“收集来源 / 整理批次 / 合并摘要 / 发布回顾”紧随其后，宽窗口使用按内容排布的紧凑状态行，窄于 720px 时两列，不为每个阶段铺设独立色块卡片。阶段读取已保存位置和真实运行状态，剩余来源为零不表示发布成功。旧运行没有阶段字段时显示“未记录”，不猜测失败位置；已提交来源清单可确认收集结束。无变化运行不显示新结果跳转，后续无需执行的阶段单独标注。

阶段下显示已保存批数、已读字符数、剩余来源和已保存导航合并数，运行中另显示排队或在途数。字符进度按码点统计，界面不展示 Unicode 术语。恢复操作先于详情：运行中可暂停，失败或暂停后沿用同一运行继续；已记录合并、发布阶段时分别显示“继续合并摘要”“重试发布”。成功叶子保留。来源失效时显示新建回顾提示，不提供无效继续。原始错误默认折叠，展开后的完整文本最多占 240px 高度，可滚动、选择复制和键盘聚焦；错误与恢复操作位于批次树之前。结束时间、覆盖区间、报告状态和已有摘要收进“运行详情与配置”，已保存配置在其中再次折叠。

“已保留事实与来源”展开后才查询既有批次接口，每页 10 批，按本页持久记录组成项目、会话、批次层级。项目使用可用名称，会话优先使用保存来源的标题；只有已保存批次标记“已保存”，不创建未落库的待执行、在途或失败叶子，也不把本页数量当作项目总量。批次摘要收起时最多两行，展开后保留完整摘要、事件、实体、变化、关系及原文片段。来源显示消息 ID、码点范围及版本；长原文局部滚动。原生 details/summary 保留键盘展开和可见焦点，轮询不主动展开用户收起的会话。加载、空批次和读取失败分开显示，失败可重试；换页失败不显示上一页批次，切换 run 后旧响应失效。暂停状态为“未完成，可继续”，手动回顾软预算暂停后在工作回顾页提示去活动继续，不显示完成通知。

## 自动监督设置

2026-09-23 当前已实现“模型超时与并发”表单：心跳报告与监督者整理分别设置，均为 30 至 600 的整数秒，默认 240；监督模型并发数为 1 至 4 的整数，默认 1。保存真实字段 `heartbeatReportTimeoutSeconds`、`supervisorOrganizeTimeoutSeconds`、`supervisorModelConcurrency`；无效输入不能提交，设置加载/保存中或锁定时禁用，失败保留草稿并提供重试。超时以阶段读取设置的时点为准，不改变已冻结的值；并发数影响后续派发，降低上限不打断在途请求。

并发说明明确报告和监督整理共用上限，排队不计入模型超时；普通聊天不受此设置限制，但仍与监督竞争上游额度。表单不宣称提供商全局并发、RPM、TPM 或 Retry-After 限流已实现。

模型超时不包含数据收集与保存，直连模型另有独立 600 秒传输超时。“回顾算法”表单提供“每次读取来源条数”“每批文本量”“每批消息数”和“单次整理时长”，显示默认值及合法范围，使用“保存回顾算法”独立提交。文本量内部仍按 UTF-16 单元计算，界面不要求用户理解编码单位。保存经 App 的现有设置回调进入共享设置存储，加载/保存/锁定时禁用，失败保留草稿。取值以[当前设置合同](./review-scheduling-design.md#当前设置合同)为准。帮助说明执行时间达到软预算后，正在处理的批次完成并保存，再暂停，可从活动记录继续；已保存配置用“同时处理任务数”解释并发，说明实际并发还受当前监督设置限制。

对应 US-S22 至 US-S24。“自动监督”先显示计划列表，点击创建或编辑才打开 Modal；复用原表单，不保留页面内副本。表单展示名称、项目范围、每日或每周频率、指定时间、回顾窗口（1 至 720 小时）和历史保留（1 至 365 天）；每周显示星期选择。时区常显，新建使用本机时区，编辑保留计划原时区。列表上方帮助说明选择每日或每周时间、保存并启用后自动运行。

无计划时显示“尚未配置自动监督，目前仅支持手动回顾”；全部暂停时另行说明。加载或首次读取失败不显示未配置状态。打开页面、Modal 或填写字段均不创建计划，只有点击“保存并启用计划”才提交创建。已有计划显示范围、周期、时区、回顾窗口、保留期限和启停状态，保留编辑、暂停、恢复、立即运行、执行记录和确认删除；暂停时不显示待执行的下次时间，编辑保存不改变暂停状态。

Modal 按[共享表单 Modal 规则](../../../UI-DESIGN.md#615-表单-modal)复用 header、body、footer：标题左侧、带本地化名称和工具提示的 X 右侧；底部取消次按钮、保存主按钮整体右对齐。标题和操作区保持可见，仅表单内容滚动。表单使用独立字段容器，不嵌套设置表单；窄窗口表单单列，保留共享窗口安全边距。

沿用整窗 Portal、共享遮罩、背景 inert、焦点循环与关闭后焦点恢复；初始焦点进入名称。X、Escape、取消或点击遮罩关闭时，有未保存修改先确认；确认初始焦点为继续编辑，Escape 或 X 只返回编辑，点击遮罩不放弃修改。保存期间禁止关闭和重复提交，失败在表单内显示并保留草稿。

界面及可访问名称统一使用“自动监督 / 回顾”，保留内部 heartbeat 标识及已有计划名称、报告正文。表单继续使用共享控件和容器响应式布局，建议及审计无需先进入即可配置计划。

### 算法配置设置目标

以下高级分组为目标交互；已接通的四项算法控件以上节为准。其余参数引用[设置配置清单](./review-scheduling-design.md#4-设置配置清单)，不在 UI 文档另设数值，不增加一级页面。

普通配置常显消息每页条数、监督并发、报告/整理模型超时和单次执行软预算。高级配置按“来源与分块”“上下文与输出”“汇总与内存”“超时与续跑”“上游额度”分组。消息页字段的常显帮助为：“每次从数据库读取的消息数；会持续读完所选范围，不限制回顾总消息数，也不决定每次发给模型的消息数。”模型批次消息数、片段数和新增字符数分别标注，避免统称“批量大小”。

字段显示单位、已确定的默认值和合法范围；补充帮助说明调大后的内存、等待或模型用量影响。允许继承的节点超时显示“继承监督整理值”及解析后的秒数；依赖模型容量的输入/输出预算显示所用模型、容量及 token 是否为估算。跨字段校验覆盖输入与输出预留之和、扇入可容纳性、软预算与硬期限顺序、退避起始与上限；错误附在字段并关联可访问说明，提交时聚焦首个错误，Main 仍作权威校验。

规划中的“保存配置”持久化后只用于新建运行，常显“已开始和待继续的回顾沿用启动时配置”。“恢复本组默认值”只修改该组草稿，经保存才生效，不开始回顾、不修改已有计划；取消编辑恢复已保存值。运行详情展示本次实际配置，继续操作沿用它；想采用新算法配置时使用“重新回顾”，说明会重新计算。当前已实现字段仍按上文的阶段读取和共享池生效方式工作，整次 run 冻结接线完成后再统一调整提示。

初次加载、读取失败、编辑、保存中、保存失败和已保存分别呈现；读取失败不填假默认值，保存失败保留草稿并允许重试。保存成功使用应用通知，字段错误就地显示，不重复通知。窄窗口按单列排列，折叠标题可键盘操作，单位和关键生效说明不藏进悬浮帮助。

只在真实 Main/存储/运行路径接通后显示相应可编辑字段；尚未实现的配置留在设计文档，不放置永久禁用的假控件。已接通但因加载、保存或依赖缺失而临时不可编辑时说明实际原因。上游额度明确显示适用连接/模型和是否包含普通聊天；未实现跨路径共享时不得标为提供商全局限制。覆盖完整性、来源校验及事实保留不提供开关。

## 工作回顾

当前页面提供全局或单项目范围，以及 1、7、30 天时间区间选择。没有自动计划也能手动回顾；成功结果显示自身冻结的范围、时间和未解决事项，可选择历史结果或进入图谱。来源筛选由本次回顾范围和时间限制；图谱详情只列出所选事件的关联来源，实体或关系列出相关事件的来源。独立的来源类型选择器尚未实现。

选择历史结果后，图谱读取该结果的成员和内容，标题显示其回顾区间和生成时间。切换时清空旧图谱和详情并显示加载状态，迟到请求不得替换新选择。确认、修订和移除反馈更新当前所选结果，后续自动回顾不改写旧结果。

手动“回顾当前进展”生成中禁用重复提交。该操作新建回顾，活动页“继续”恢复原 run；两者不得混淆。失败保留上次结果、本次范围和成功批次。手动操作不推进自动位置，删除报告也不重置自动位置。

## 会话侧栏

仅在应用已启用时挂载监督面板及固定目标控件；关闭或设置尚未加载时不挂载，也不发起面板查询。任务列表仍按原规则显示。

任务中心从上到下依次显示项目概览（含当前会话统计）、监督反馈、项目任务。

右侧通用助手工作栏中的监督卡片展示“监督反馈”，沿用现有[工作栏设计](../assistant-workbar/prd.md)的布局和执行边界。当前支持 Conversation/Task：有选中任务时跟随任务，否则跟随会话；“固定监督目标”保存当前目标，切换聊天后保持，取消固定恢复跟随。卡片显示目标、结果真实范围、回顾区间和摘要，可刷新并查看匹配来源；无目标或无匹配结果显示空态。Experiment 尚未接入。

有匹配结果时提供“在图谱中查看”，打开现有监督者页面的图谱页签并读取该结果；无匹配结果不显示入口。按钮保留原生键盘操作，进入后焦点落在图谱页签，继续使用共享 PageTabs 的方向键导航。固定目标不因跳转改变；再次点击相同或不同结果均重新定位，包括页面缓存后再次进入。结果不可用时显示错误并重试原 ID，不展示默认最新结果。

当前“继续讨论”预览实际发送会话名称、ID 和上下文，确认后发送到该会话；固定任务使用其关联会话，无法确定发送会话时禁用。切换目标使旧来源请求和预览失效。编辑预览中的引用仍属后续工作。

## 故事线图谱

使用 `supervisor` 页面壳层，最大内容宽度为 `1440px`。当前生产图谱左侧为紧凑的事件、实体和关系列表，中间为 SVG 画布，右侧为详情与来源。桌面列宽为 `216px minmax(0, 1fr) 280px`，画布获得主要空间。外圈事件按发生时间排序后等距逆时针排列，不表示实际时间间隔；起止之间保留缺口和方向箭头。内部显示真实实体名称，实线仅连接实际事件与实体，虚线仅连接实际实体关系。

实体及其影响连线复用现有 `--graph-node-*-border` 令牌；颜色用于辅助辨认实体，不代表故事分类或确认状态。选中项加粗并突出连线，其余节点降低图形强调度但保留可读文字。详情分为名称与说明、图谱关联、确认操作和来源，来源正文按需读取。图例常显，读图说明可展开。

画布每批最多显示 8 个事件、6 个实体；同时间事件分开排布。列表保留全部返回记录和完整名称，选择实体会定位到真实关联事件所在批次，选择关系会优先显示两端实体。滑块明确命名“事件浏览”，只切换当前事件，不还原实体历史状态，也不宣称完整历史回放。当前接口返回单条故事线，不复制 Demo 中的三条模拟故事。后续视图规划见[图谱设计](../story-graph/prd.md)。

按实际内容容器宽度响应：不超过 `1190px` 时变为 `184px` 列表加画布，详情移到下方；不超过 `860px` 时变为单列，画布优先，列表限制高度并独立滚动。SVG 最小宽度为 `660px`，窄屏只在画布内部横向滚动，页面本身不横向溢出。范围、时间和操作可换行。节点、关系与事件均可从列表选择，画布节点支持 Enter、Space 和可见焦点。加载、无数据、读取失败和服务不可用各自呈现，错误提供可行的恢复说明或重试入口。

隔离视觉验证使用 `tests/support/supervisor-layout-regression.tsx` 渲染生产 React 组件；所有输入标为模拟 fixture，不读取用户数据库或调用模型。`tests/supervisor-layout.electron.test.ts` 启动 Vite 与 Electron，通过 `executeJavaScript` 测量布局、`capturePage` 截图，覆盖 1440、1024、390px、浅深主题、长名称、密集事件和异常状态。可通过 `GOODBUDDY_SUPERVISOR_ARTIFACTS` 保留截图；交互预览入口为 `node tests/support/supervisor-preview.mjs`。
