### 2026-10-12 交互修订

评审发现初版 minimap 是悬浮在中部的 220 px 小条，视口指示经 `requestAnimationFrame` + React 状态更新而滞后于滚动，且没有悬停放大。已修订：

- minimap 替代消息滚动区的原生滚动条：`.chat-history-pane > .chat` 隐藏原生滚动条，minimap 高度与滚动区 `clientHeight` 一致并贴合右侧。
- 视口滑块在 `scroll` 事件和 `ResizeObserver` 回调中同步写入 `transform`，不经过 React 提交或下一帧；滚动区尺寸不变时只写 `transform`，不读布局。
- canvas 仅在消息变化、行高测量变化、尺寸变化或展开／收起时重绘；普通滚动不重绘。
- 悬停时展开为 96 px（窄屏 64 px）的缩略长图：用户消息靠右、助手消息靠左并按内容长度给出线宽；拖动中离开不收起。
- 点击轨道将滑块中心移到指针处，拖动滑块保持抓取偏移；滚轮转发给消息区；保留 Home／End／PageUp／PageDown；无障碍角色为 `scrollbar`，文案使用 i18n `chat.minimap`。
- 验证：minimap、历史窗口和时间线定向测试 65/65；web 类型检查和改动文件 lint 通过；`App.test.tsx` 342/350，8 个失败与此前相同（等待状态圆点异步断言）；`npm run build:bundle` 通过。
- `npm run perf:app` 通过：长会话打开帧 p95 8.6 ms、无长任务；长会话滚动帧 p95 8.6 ms、无长任务；`stream-seeded`／`stream-and-type` 无长任务、帧 p95 8.5 ms；24 次切换后 DOM 2,449、堆 23 MB，后半段增长 0.1 MB。
- 未验证：真实鼠标悬停／拖动的视觉效果仍需在桌面端人工确认；多轮交替与低端机模拟仍未做。
