# 外部应用 PRD

| 项目 | 内容 |
| --- | --- |
| 状态 | 大部分已实现，进度见 [progress](./progress.md)；界面参考 [Demo](./demo.html) |
| 接入模型 | 以 OpenClaw 的飞书插件和企业微信插件为准 |
| 入口 | 左下角“应用 › 管理应用”（应用中心） |

## 1. 问题

- 微信、企业微信、钉钉、Telegram 的配置放在设置中心的“消息通道”里，只能收发消息，用不了平台上的文档、网盘、日程等数据。
- 飞书还没有接入。
- 用户希望从应用中心统一连接和管理这些平台，在对话里直接读写平台内容。

## 2. 目标与非目标

目标：

- 应用中心统一管理外部应用的连接、消息和工具。
- 一个平台账号一套凭据，扫码即可完成；不要求用户理解开放平台的权限配置。
- 飞书、企业微信提供文档类工具，可以在桌面对话中使用。
- 现有四个消息通道迁入应用中心，凭据、白名单和通道项目原样保留。

非目标：

- 不做单独的用户 OAuth，不做访问范围选择，不做按操作区分的权限矩阵和“桌面确认”。
- 不上架 GoodBuddy 自有的平台应用（应用商店、第三方应用）。
- 钉钉暂不提供文档工具。
- 企业微信不接入自建应用（CorpID、CorpSecret、AgentID），不处理可信 IP。
- 一期不支持同一平台连接多个账号。

## 3. 平台差异

| 平台 | 凭据 | 连接方式 | 消息 | 工具 | 工具身份 |
| --- | --- | --- | --- | --- | --- |
| 飞书 | App ID、App Secret；版本可选飞书或 Lark | 扫码创建自建应用，或手动填写；长连接接收 | 私聊、群聊 | 文档、知识库、云空间、多维表格、群信息、权限管理 | 应用身份，只能访问共享给该应用的内容 |
| 企业微信 | 智能机器人 Bot ID、Secret | 扫码创建 API 模式智能机器人，或手动填写；长连接接收 | 私聊、群聊 | 文档管理、在线文档、在线表格、智能表格、智能文档、在线 PPT、微盘、媒体文件、日程、会议、待办、通讯录、邮件（收发，默认关闭）、消息（与官方 Skill 对应） | 授权人本人，可访问本人有权限的内容 |
| 钉钉 | Client ID、Client Secret | 手动填写；Stream 长连接 | 私聊、群聊 | 无 | — |
| 微信 ClawBot | 扫码绑定 | 扫码 | 绑定账号的私聊 | 无 | — |
| Telegram | Bot Token | 手动填写 | 私聊 | 无 | — |

依据：

- 飞书工具分组、默认值和扫码行为来自 OpenClaw 飞书文档。权限管理默认关闭。
- 企业微信只用智能机器人，来自腾讯维护的 OpenClaw 插件和 `wecom-cli`：业务工具使用 Bot ID 和 Secret；`wecom-cli` 的文档搜索只返回调用者本人有权限的文档。
- 企业微信自建应用的文档接口只能访问应用自己创建的文档，网页授权只返回 userid，不能满足个人文档访问，因此不采用。

## 4. 功能要求

### FR-1 应用中心

GoodBuddy 暂不支持第三方插件，飞书、企业微信、钉钉、微信 ClawBot、Telegram 都是内置应用，称为“平台应用”。应用中心分两组：

- **工作区应用**：知识库、魔法笔记、监督者等现有应用，行为不变，可排序、可常驻左侧。
- **平台应用**：顺序固定为飞书、企业微信、钉钉、微信 ClawBot、Telegram。每行显示连接状态（应用关闭时显示“已关闭”）、账号（Bot ID / App ID / Client ID / 微信账号）和能力标签（发送者数量、群聊响应、已开启的工具类别或“只有消息”），以及打开后去哪里。列表下方提示“每个平台连接一个账号”。不常驻左侧，不出现在左下角“应用”菜单中，因此不参与排序。

平台应用的操作：

- 未配置：只显示“连接”，进入该应用设置的“连接”页。
- 已配置：显示“打开”和“应用设置”；应用关闭时“打开”不可用。
- “打开”：飞书、企业微信在对话右侧工作区打开（或切换到）该平台的面板，见 FR-6；钉钉、微信、Telegram 进入它的通道项目，查看收到的会话。
- “启用应用”就是“连接”页的启用开关，直接读写该通道现有的启用状态，不在应用设置中另存一份。它同时控制消息和工具：关闭后停止接收消息，对话、右侧面板和 `@` 中也不再提供该应用的工具。工具页没有单独的总开关。
- 应用排序和常驻配置（`applicationNavigation`）不包含平台应用，现有配置无需迁移。

一期每个平台只能连接一个账号，每个平台固定一行。要换账号，先在“连接”页“断开并删除本机凭据”（确认后关闭应用，删除凭据和允许的发送者；企业微信同时删除工具授权；通道项目和历史会话保留），再重新连接。这与现有消息通道每个平台一份配置的存储方式一致。

### FR-2 连接流程

飞书和企业微信在应用设置的“连接”页完成连接（一期不做单独的三步向导，见第 8 节）。

- 扫码创建为推荐方式。扫码完成后应用立即启用，扫码人的用户 ID 成为唯一允许的发送者，工具按默认类别可用。读不到扫码人 ID 时应用仍启用，但不处理任何消息，需在“消息”页填写发送者。
- 手动填写时，私聊策略默认为“白名单”，白名单为空时不处理任何消息。
- 二维码有过期时间（飞书约 10 分钟，企业微信 5 分钟），过期后可重新生成。
- 飞书手机端扫码没有反应时，提示改用手动填写。
- 企业微信提示无权创建机器人时，提示联系管理员开放智能机器人创建权限。

钉钉、Telegram 在设置的“连接”页直接填写凭据；微信沿用现有扫码绑定。

### FR-3 应用设置

设置页有三个标签，没有工具的应用不显示“工具”（“使用记录”见第 8 节）：

| 标签 | 内容 |
| --- | --- |
| 连接 | 启用开关、凭据（扫码创建、手动填写或替换、测试连接）、断开并删除本机凭据 |
| 消息 | 允许的发送者、群聊被提及时是否响应、通道项目（工作目录、处理后端）。微信只处理绑定的本人，不支持群聊；Telegram 不支持群聊 |
| 工具 | 工具身份说明；按类别开关；敏感类别默认关闭；“消息里能否使用工具”开关 |

关闭“启用”后停止接收消息，对话中也不再提供该应用的工具；凭据和设置保留。

### FR-4 私聊和群策略

- 私聊策略：仅我自己、白名单、配对审批、关闭。配对审批时，陌生人的首条消息在桌面端等待批准。
- 群策略：仅指定群（需要 @）、所有群（需要 @）、关闭。
- 不在许可范围内的消息直接忽略，记录到使用记录。

### FR-5 工具

- 每个类别一个开关，关闭的类别不出现在对话的工具列表中。
- 敏感类别默认关闭：飞书“权限管理”，企业微信“消息”。邮件默认关闭。
- 飞书工具由 GoodBuddy 内置，操作清单固定。
- 企业微信工具来自官方 `wecom-cli` 和官方 Skill 说明，类别与官方 Skill 一一对应：文档管理（搜索、最近浏览、重命名、成员权限与加入规则）、在线文档、在线表格、智能表格、智能文档、在线 PPT、微盘、媒体文件、日程、会议、待办、通讯录、邮件、消息。官方的“文档管理”同时包含搜索和改权限，无法拆开，因此默认开启并在界面上注明含改权限。在线 PPT 和本地 docx 生成会运行官方 Python 脚本（见 7.1）。
- 企业微信的类别开关由 GoodBuddy 强制执行：不属于已开启类别的命令会被拒绝（见 7.1）。
- 飞书“知识库”依赖“文档”：关闭文档时知识库类别显示为不可用，工具、右侧面板和 `@` 都不提供知识库。
- 桌面对话始终可以使用已开启的工具。
- 消息会话能否使用工具由一个开关决定，默认关闭。关闭时只回复文字，不调用该应用工具。
- 写入不需要额外确认。对话中每次飞书、企业微信工具调用下方显示结果卡片：读取或写入了哪类内容、标题、数量和“打开原文”；写入时提示 GoodBuddy 无法撤销、可在平台文档的历史版本中恢复。

### FR-6 右侧工作区面板

飞书、企业微信不提供独立页面，而是作为对话右侧工作区的面板，便于边对话边查资料。

- 面板与现有“笔记”面板同类：单实例、可关闭、不随项目切换。默认不打开。
- 打开方式：右侧工作区的“＋”菜单，或应用中心的“打开”。已打开时切换到该面板。应用开启但工具不可用（未授权、凭据缺失）时，“＋”菜单列出该平台、原因和“前往处理”。
- 一栏布局：标题行（平台、工具身份和账号、应用设置入口）、搜索框、空间下拉、新建和上传按钮、类型筛选、数量、结果列表。每条结果显示类型、路径（有时）和更新时间，提供“打开原文”和“用于当前对话”。搜索时空间下拉不可用，清空搜索后回到当前空间。
- 飞书：空间下拉为“全部空间”（应用云空间根目录）和各知识空间；进入后可逐层浏览。类型为文档、知识库、多维表格、文件，空间和文件夹始终显示。搜索按标题在应用可见的空间和文件夹中查找，结果显示所在路径。看不到内容时提示按飞书 Wiki FAQ 把机器人所在群加为知识空间成员，或“添加文档应用”。新建：在云空间新建文档（需要“文档”），在知识空间新建页面（需要“知识库”）；上传：在云空间文件夹上传一个本地文件（≤ 20MB，需要“云空间”），文件由主进程的文件对话框选择。
- 企业微信：空间下拉为“最近浏览”“我创建的”（近 30 天，官方文档管理 Skill 的查询方式，需要“文档管理”）和“微盘”（最近浏览的微盘文件，需要“微盘”）。类型为文档、表格、微盘。只显示授权人有权限的内容；日程、待办和会议在对话中使用。新建：空白在线文档（需要“在线文档”）；上传：一个本地文件到微盘默认空间（需要“微盘”）。
- 钉钉、微信、Telegram 只有消息，不提供面板。

### FR-7 对话引用

在桌面对话的输入框输入 `@` 可以引用飞书、企业微信中的单篇文档。

- 触发：`@` 位于开头或空白之后（邮箱地址中的 `@` 不触发）。继续输入的文字作为标题搜索词。弹窗跟随 `@` 的位置，出现在 `@` 所在行的上方、左边与 `@` 对齐；靠近输入框右侧时向左收回，保持完整显示。
- 范围：只列出工具已启用的平台，结果只包含当前连接身份有权访问的内容：
  - 飞书按应用身份，在共享给应用的知识空间和云空间文件夹中按标题过滤（飞书文档搜索接口需要用户身份，一期不做用户 OAuth）。需要“文档”“知识库”或“云空间”类别之一开启。
  - 企业微信按授权人本人身份调用官方文档搜索。需要“文档管理”类别开启。
  - 工具已启用但不可用（未授权、凭据缺失、相关类别关闭）的平台显示原因和“前往处理”。
- 选择：方向键和 Enter/Tab 选择，Esc 关闭；选中后输入的 `@搜索词` 被替换为引用标签，标签可删除。每条消息最多 5 篇，同一篇不重复添加。
- 发送：引用转成一段说明附在消息后，写明平台、标题、链接、文档 ID 和读取方式，要求模型用对应工具读取，读取失败时说明原因。只有引用没有文字时也可以发送。
- 发送后由工具按当时的开关和平台权限重新检查；一期不预读文档内容，不支持引用整个空间。
- 消息通道发起的会话不提供 `@`。

### FR-8 迁移

- 设置中心移除“消息通道”分类。
- 微信、企业微信、钉钉、Telegram 的现有凭据、白名单和通道项目迁入对应外部应用，不需要重新绑定。
- 现有白名单映射为“白名单”私聊策略。
- 产品内不显示迁移提示，由发布说明告知。
- 现有企业微信通道使用智能机器人凭据，迁移后可直接开启工具。

## 5. 限制

- 飞书扫码创建应用使用的接口没有公开文档，可能变化；失败时用户只能手动填写。
- 企业微信业务工具的服务目录由服务端在线下发，可用工具可能随企业微信更新变化。
- 企业微信和飞书工具一期不支持 DeepSeek Harness（见 7.1、7.2）。
- 企业管理员可能禁止员工创建智能机器人，此时无法扫码连接企业微信。
- 飞书工具以应用身份运行，读不到未共享给应用的个人文档。
- 平台写入无法由 GoodBuddy 撤销。

## 6. 验收

1. 从应用中心扫码连接飞书和企业微信，完成后私聊策略为“仅我自己”，工具按默认值开启。
2. 手动填写凭据后，白名单为空时不处理任何消息。
3. 在桌面对话中读取并写入飞书文档、企业微信文档；关闭某类工具后，该类命令被拒绝。
4. 未开启“允许消息会话使用企业微信工具”时，消息会话中没有企业微信工具。
5. 关闭应用后不再接收消息，对话中没有该应用的工具；重新开启后恢复。
6. 升级后，原有四个消息通道无需重新绑定即可继续收发消息，设置中心不再有“消息通道”。
7. 扫码超时、无权创建机器人、凭据无效时有明确提示和替代路径。
8. 直连模型、OpenCode、Continue 都能使用企业微信工具。
9. 已连接的平台不再提供“连接”入口；断开后本机凭据和 `wecom-cli` 配置目录被删除，可以重新连接其他账号。

## 7. 实现方式

### 7.1 企业微信：官方 CLI，由 GoodBuddy 代为执行（已实现）

使用官方 [`wecom-cli`](https://github.com/WecomTeam/wecom-cli)（`@wecom/cli`，MIT）和官方 Skill 说明，与 OpenClaw 一致；区别是命令不交给模型的 shell，而由 GoodBuddy 执行：

- **三个内置工具**：`wecom_guide` 按需读取已开启类别的官方 Skill 说明（随应用打包在 `resources/wecom-skills`）；`wecom_cli` 执行一条 `wecom-cli` 命令；`wecom_script` 运行文档和在线 PPT 技能附带的官方 Python 脚本（`build_docx.py`、`build_page.py` 等）。GoodBuddy 校验命令属于已开启类别，拒绝 `auth`、`cache`、`schema`。每次调用都按当前设置重新校验，关闭类别或应用立即生效。
- **凭据**：专用目录 `<userData>/wecom/config`，通过 `WECOM_CLI_CONFIG_DIR` 指定，不读取用户自己的 `~/.config/wecom`，也不继承环境中的 `WECOM_CLI_*`。扫码由 GoodBuddy 直接调用 wecom-cli 1.3.4 使用的扫码接口（`work.weixin.qq.com/ai/qc/generate` 和 `/ai/qc/query_result`，无公开文档），拿到新机器人的 Bot ID 和 Secret 后：调用 `auth init --bot-id/--secret` 为工具签发凭据；同一个机器人加密存入企业微信消息通道，`identity whoami` 读到的扫码人作为唯一允许的发送者并启用通道（读不到时不启用，需在“消息”页填写发送者）。这样一次扫码同时配置工具和消息通道，与飞书扫码一致。扫码入口和手动填写都在应用设置的“连接”页，与机器人 ID、Secret 放在一起；在“连接”页手动填写新机器人并保存后，同样调用 `auth init --bot-id/--secret` 为工具授权。“工具”页只放授权状态、类别开关和断开，未授权时引导回“连接”页；已在“连接”页保存但工具未授权（如旧版本保存的）时提供“使用消息通道的机器人”。断开时删除该目录。凭据目录对模型不可见。
- **内置，不联网安装**：面向私有化部署，`wecom-cli` 平台二进制（固定 1.3.4）在打包时放进安装包的 `resources/runtimes/wecom/bin`，运行时不访问 npm。打包脚本 `build/wecom-resources.cjs` 按 `resources/wecom-artifacts.lock.json` 校验 npm 包的 sha512 后解出。目前提供 Windows x64、macOS x64/arm64、Linux x64/arm64；其他架构（如 Windows arm64、Linux loongarch）的安装包不含企业微信工具，界面会提示。
- **执行方式**：通过现有内置工具网关提供给直连模型、OpenCode、Continue。DeepSeek Harness 目前不接收内置数据工具，暂不可用。
- **技能脚本**：脚本在 `<userData>/wecom/downloads` 中运行，使用 GoodBuddy 自建的 Python 虚拟环境 `<userData>/wecom/python`（基于本机工具环境的托管 Python 3.13）。依赖 python-docx、python-pptx、openpyxl、Pillow、pypdfium2 及其传递依赖的 wheel 也内置在安装包 `resources/runtimes/wecom/wheels` 中，用 `pip install --no-index --find-links` 离线安装，每个 wheel 的地址、大小和 SHA-256 都记录在锁文件里。只能运行已开启类别（文档、在线 PPT）的脚本，输入文件只能写入工作目录；脚本中的 `wecom-cli` 使用 GoodBuddy 的凭据。
- **消息会话**：默认不提供；用户开启“允许消息会话使用企业微信工具”后才提供。

### 7.2 飞书：内置工具 + 长连接消息通道（已实现）

按 OpenClaw 飞书插件（MIT）的工具分组和默认值实现，飞书成为第五个消息通道：

- **凭据**：一个飞书企业自建应用的 App ID / App Secret，保存在消息通道设置中（加密），消息和工具共用。可以手动填写，也可以“扫码创建飞书应用”（沿用 OpenClaw 的 accounts 注册接口，无公开文档）；扫码完成后扫码人的 open_id 成为允许的发送者，并在应用创建文档时获得完全访问权限。支持飞书和 Lark 国际版。
- **消息通道**：用官方 `@larksuiteoapi/node-sdk` 的 WSClient 长连接接收 `im.message.receive_v1`，不需要公网地址；按 open_id 白名单过滤，群聊只在 @机器人 时处理；回复通过 `im/v1/messages/{id}/reply`。暂不支持图片和附件。测试连接会获取 tenant token 并读取机器人信息。
- **工具**：`feishu_doc`、`feishu_wiki`、`feishu_drive`、`feishu_bitable`、`feishu_perm`、`feishu_app_scopes`，以应用身份直接调用 Open API。类别开关由 GoodBuddy 强制，权限管理默认关闭；默认不提供给消息会话。写文档时先用飞书的 Markdown 转换接口再插入块。
- **右侧面板**：浏览应用可访问的知识空间和云空间文件夹，“打开原文”和“用于当前对话”。
- **存储**：数据库 v64 把通道 CHECK 约束扩展到 `feishu`，并新增飞书通道项目。
- 不采用飞书官方 `lark-mcp`：它仍是 Beta，不支持文件上传下载和云文档编辑，用户身份需要另配 OAuth 回调。

### 7.3 通用约束

- 外部应用的工具由应用中心管理，不出现在“能力与工具”的 Skills 或 MCP 列表中。工具通过内置工具网关提供，不经过模型的 shell，也不向任何 shell 注入配置目录。
- 凭据不进入对话上下文。每个平台一份凭据，由 GoodBuddy 加密保存。
- 关闭应用（通道的启用状态）：工具服务的可用类别立即为空，对话、右侧面板和 `@` 都不再提供该应用。
- 消息会话：“消息里能否使用工具”关闭时，`origin === 'channel'` 的请求不获得该应用的工具（`ipc.ts` 中按请求来源判断）。

### 7.4 已知限制

- 改文档权限包含在默认开启的“文档管理”里，与官方 Skill 一致，无法单独关闭。
- 官方服务目录在线下发；新版本 CLI 或 Skill 需要随 GoodBuddy 版本一起更新（`WECOM_CLI_VERSION` 和 `resources/wecom-skills`）。
- 内置制品只在打包时从 npm 和 PyPI 下载并按锁文件校验；运行时完全离线。
- 技能脚本要求 Python 3.13（内置 wheel 按该版本打包）；自定义的其他版本 Python 会被拒绝并提示改用托管 Python。
- 一个命令最长 2 分钟，输出最多 256KB；下载文件保存在 `<userData>/wecom/downloads`。
- 没有 Python 时提示到本机工具环境安装托管 Python；托管 Python 本身的下载遵循本机工具环境的下载源设置。
- 飞书工具以应用身份运行，读不到未共享给应用的个人文档；飞书扫码创建应用的接口没有公开文档，可能变化。
- 飞书通道只处理文本和富文本消息，回复只发文本。
