## 1. 信息架构

“工具执行环境”是设置中心“模型与执行”分组下的独立一级分类（`tool-environment`），
副标题为“Node.js、Python 和 pip”。Skills 和 MCP 不在设置中心：2026-11-13 起它们是
应用中心的“Skills”“MCP” Tab，见[应用中心 UI](../application-tool-navigation/ui-design.md)。
设置中心不再提供“能力与工具”分类。

“工具执行环境”不放入任一 Runtime 专属卡片。页面顶部持续显示：

> 用于新启动的本机 Runtime 和 stdio MCP；不修改系统环境，也不应用于普通终端或远程主机。

## 2. 页面结构

```text
设置中心 › 工具执行环境

  范围说明

  工具下载源
    原生地址 / OSS 镜像

  Node.js 卡片
    来源
    当前状态
    自定义候选或路径操作
    测试环境

  Python 卡片
    来源
    当前状态
    安装/更新/删除或自定义路径操作
    测试环境
```

页面内的区块顺序固定为工具下载源、Node.js、Python，不增加页签。

## 3. 与 Skills、MCP 的关系

Skills 和 MCP 依赖本页选择的 Node.js 与 Python，但界面上不再与本页组成一组 Tab：

- 本页只配置解释器和下载源，不显示 Skill 或 MCP 列表。
- 应用中心的 Skills、MCP Tab 不嵌入本页，也不提供跳转到本页的入口。
- 切换设置分类或应用中心 Tab 都不修改任何 Skill、MCP 或工具环境值。

“MCP / 自定义 MCP”的添加和编辑共用应用中心上方的子 Modal。打开后聚焦名称输入框，
父弹窗与工作区保持不可交互；Tab 和 Shift+Tab 在编辑器内循环。X、取消、Escape、
遮罩及保存成功均返回原添加或编辑按钮，Escape 只关闭编辑器。保存期间禁止关闭，
失败保留输入。右侧浏览器沿用应用级 Modal 的视图释放规则，编辑器关闭后仍由父弹窗
保持隔离，父弹窗关闭后恢复网页。

## 4. 工具下载源

使用原生 Radio Group：

```text
工具下载源
选择 GoodBuddy 受管 Runtime 和工具链的下载通道。

● 原生地址（默认）
  从各工件的固定上游地址下载。

○ OSS 镜像
  从 GoodBuddy OSS 下载相同工件。
```

邻近说明：

> 下载开始后会固定本次来源；失败时不会自动切换。该设置不影响模型、应用更新、Agent、
> pip/npm 依赖或用户配置的网络地址。

切换设置即时保存，不触发下载，不取消活动任务。成功通过应用通知反馈；保存失败恢复最后
确认值并在 Radio Group 附近显示错误。

## 5. 工具环境来源选择

每张卡片使用原生单选语义，只提供：

1. **GoodBuddy 托管（推荐）**
2. **自定义环境**

不显示“自动选择”“系统安装”“指定路径”三个交叉选项。自定义环境选中后，在同一区域展示
检测候选下拉框和“选择其他可执行文件”次操作。

“自定义环境”单选项始终可操作。尚无候选或已保存路径时，点击只展开选择区域并保持当前
实际来源，不把入口禁用，也不自动选择第一个候选。选择区域显示“刷新候选”和“选择其他
可执行文件”；只有用户明确选择且 Main 验证成功后才保存并切换来源。

文件选择取消不显示错误、不发送成功通知且保持选择区域展开。验证失败在对应 Node/Python
卡片的路径操作附近显示，保留原来源和原路径；不得只在页面顶部显示错误。刷新后出现候选
时通过正常列表更新呈现，不改变当前来源，焦点保持在触发操作或用户随后选择的候选上。

候选项格式：

```text
Node.js v22.14.0 · C:\Program Files\nodejs\node.exe
Python 3.13.2 · C:\Python313\python.exe
```

版本和绝对路径不能只放在 Tooltip 中。

## 6. Node.js 卡片

```text
Node.js

● GoodBuddy 托管（推荐）
  Node.js vXX · 已就绪
  npm 11.x · npx 11.x

○ 自定义环境
  [Node.js v22.x · C:\Program Files\nodejs\node.exe ▼]
  [选择其他可执行文件]

[测试环境]
```

托管 Node 随应用提供，不显示安装和删除操作。测试结果分别显示 Node、npm、npx，不能用
Node 成功代替整套组合成功。找不到配套 npm/npx 时，自定义 Node 可以保存，但状态显示
“Node.js 已就绪，npm/npx 不可用”。

## 7. Python 卡片

托管 Python 未安装：

```text
Python

● GoodBuddy 托管（推荐）
  尚未安装
  [安装]

○ 自定义环境
  [Python 3.13.x · C:\Python313\python.exe ▼]
  [选择其他可执行文件]
```

安装中使用卡片内进度：

```text
正在下载 Python 3.x
[================------] 68%
[取消]
```

安装后显示：

- Python 版本和架构。
- pip、venv 和 SSL 诊断状态。
- 安装占用空间。
- 有更新时的“更新”操作。
- “删除托管 Python”危险次操作。

删除确认说明受影响范围，不要求输入确认文字：

> 删除后，依赖托管 Python 的本机 SKILL 和 stdio MCP 将不可用。系统 Python、自定义环境
> 和项目文件不会被删除。

## 8. 两层状态

每张工具卡展示工具环境状态：

- 已就绪
- 尚未安装
- 正在安装
- 路径不可用
- 部分可用，例如 npm/npx 或 pip/venv 缺失
- 测试失败
- 可更新

SKILL/MCP 的能力详情展示能力依赖状态：

- 依赖已验证
- 依赖未验证
- 缺少第三方包
- 入口不可用

工具执行环境页不掌握具体 SKILL/MCP 的验证证据，因此不显示固定的“依赖未验证”占位
区块。只有对应能力产生真实验证结果后，才在该能力详情中展示上述状态。

不得把工具卡的“已就绪”复用为某个 SKILL 或 MCP 的“完全可用”。

## 9. 生效与刷新

保存后在卡片中持续显示：

> 对新启动的本机 Runtime 和 stdio MCP 生效。已运行进程不会中途切换环境。

设置保存成功、安装成功、删除成功和重新检测成功使用应用通知。版本、路径、安装进度和
阻塞错误留在卡片内，不同时显示重复通知。

## 10. 错误与恢复

- 自定义路径失效：保留路径和来源选择，显示“重新检测”和“选择其他文件”。
- 下载失败：保留已验证旧安装和安装按钮。
- 诊断部分失败：逐项显示失败项，保留成功项。
- 取消安装：恢复“尚未安装”或原已安装版本。
- 字段错误：就地关联到选择控件。
- Runtime/MCP 已运行：不显示为错误，只说明新进程生效。
- 工具下载源失败：保留当前选择，显示实际来源和重试，不提示自动回退。

## 11. 无障碍与键盘

- 外层使用 `tablist`/`tab`/`tabpanel`，支持左右方向键、Home、End 和 roving focus。
- 每个外层 `tab` 通过共享组件准确关联自己的 `tabpanel`。
- 来源使用 `radiogroup`/`radio` 语义。
- 安装、测试、更新、删除和文件选择使用语义按钮。
- 下载进度使用可命名的 `progressbar`。
- 状态不只依赖颜色，必须包含文字。
- 尚无自定义候选时不得禁用“自定义环境”入口；真正因活动操作禁用的控件仍提供可理解的
  邻近说明。
- 切换到自定义环境后，焦点按正常 Tab 顺序进入候选选择框。
- 对话框关闭后焦点回到触发操作。
- 窄屏时卡片操作换行，不压缩版本和路径到不可读宽度。

- 自定义环境

- 能力依赖已验证
- 新启动的本机 Runtime 和 stdio MCP

- 原生地址
