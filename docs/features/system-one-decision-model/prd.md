# System One 决策模型产品需求

## 1. 用户问题

GoodBuddy 当前的模型连接主要面向文本生成。对于“选择角色”“判断是否需要某项处理”“给任务分级”这类工作，文本模型需要先生成内容，再由应用解析结果。这个过程增加延迟，也让应用承担格式解析和不确定输出的处理成本。

System One 接口提供 `choice`、`noul` 和 `score` 三类结构化决策。GoodBuddy 需要把它作为独立的决策模型能力接入，并首先用于自动选择 Assistant 角色。

## 2. 产品目标

- 用户可以保存一个 System One 模型连接，并使用 Ollama 局域网地址或兼容的远程服务。
- GoodBuddy 可以向 `/v1/systemone` 发送文本或 JSON 状态和类型化问题，读取结构化答案、概率、置信度和用量。
- 用户可以指定一个 System One 连接用于角色选择。
- 开启自动角色选择后，GoodBuddy 根据当前任务选择一个已配置角色，并继续使用该角色绑定的聊天模型执行任务。
- 角色选择发生在 GoodBuddy Main 的 Runtime 执行前置阶段，与当前使用的 Runtime 无关；本地模型、OpenCode、Continue 和远程 Agent 都使用同一选择结果继续执行。
- 选择模型不可用、返回无效角色或结果不确定时，任务仍能沿用现有路由回退路径。
- 协议层可以复用于后续决策用途，避免每个用途重复实现 Provider 调用。

## 3. 首期范围

### 3.1 包含范围

- System One 模型连接协议。
- 无 API Key 和 Bearer API Key 两种认证方式。
- `choice`、`noul`、`score` 三种文本决策问题。
- 连接配置校验、请求超时、取消、响应校验和错误反馈。
- 一个全局角色选择模型配置。
- 使用 `choice` 从 Assistant 角色候选集中选择角色。
- 角色选择失败时回退到现有智能路由和默认角色。
- 在设置中显示当前角色选择模型及其启用状态。

### 3.2 暂不包含

- 使用 System One 生成聊天回复、代码或解释文本。
- 将 System One 连接用于普通对话模型选择。
- 首期图片 `box` 决策。
- 首期知识库重排、记忆筛选、回答审核和意图路由的用户入口。
- 让 System One 直接决定工具调用、权限或不可逆操作。

## 4. 功能需求

### FR-1 独立协议

模型连接支持 `system-one` 协议。该协议使用 `/v1/systemone`，请求包含模型名、状态和命名问题，响应包含模型名、答案和用量。

System One 连接不出现在普通文本聊天模型的选择列表中，也不能被 OpenAI Chat Completions、OpenAI Responses 或 Anthropic Messages 调用链当作聊天模型使用。

### FR-2 连接配置

用户可以配置：

- 连接名称；
- 基础地址；
- 模型名称，例如 `d3`、`nimble` 或 `jev-latest`；
- 无认证或 API Key 认证；
- 自定义请求头。

基础地址允许用户填写服务根地址或带 `/v1` 的地址，系统在请求时规范化为 `/v1/systemone`。

### FR-3 角色选择模型

用户可以在一个 System One 连接上开启“用作角色选择模型”。全局同时只能有一个角色选择模型。切换到另一个连接后，旧连接自动失去该用途。

“启用角色路由”是自动选角总开关；模型用途绑定不会开启角色路由。关闭总开关时保留绑定，但不调用决策模型或关键词路由，也不显示会话中的“自动”标记。开启总开关后，有绑定时优先使用决策模型，无绑定时使用关键词路由。

只有 System One 连接显示该开关。删除当前角色选择模型时，角色选择用途被清空，现有手动和关键词路由继续可用。

### FR-4 自动选择角色

当用户启用了角色路由、没有手动指定角色且绑定了角色选择模型时，GoodBuddy 将当前任务和可用角色的简短说明提交为一个 `choice` 问题。

每个候选角色使用稳定 ID。模型返回的选择只有在对应 ID 仍然存在且角色可用时才会生效。

### FR-5 选择可信度

GoodBuddy 记录选择结果中的选择项、概率和置信度。结果满足当前路由接受条件时才执行选择；否则进入现有智能路由或默认角色。

首期接受条件由逻辑设计和实现共同确定，至少包括：返回角色 ID 有效、答案结构合法、模型请求成功。阈值不得写入 Renderer，也不得让用户输入任意路由阈值覆盖系统校验。

### FR-6 回退和错误

下列情况不得让普通任务直接失败：

- 连接不可达或超时；
- 请求被取消；
- 服务返回 4xx 或 5xx；
- 响应不是合法 System One 答案；
- 返回的角色 ID 不存在；
- 结果不满足接受条件。

任务按现有路由规则继续处理。连接错误通过应用通知或任务状态反馈给用户，保留可操作的错误原因。

### FR-7 后续用途扩展

协议服务必须能够复用到其他决策用途。后续用途使用独立的用途绑定和问题定义，不修改角色选择的结果解释规则。

## 5. 用户体验

设置中的模型连接列表区分聊天模型、图片模型和决策模型。决策模型连接展示协议名称和认证状态。

System One 连接详情提供一次最小连接测试，展示请求是否成功、模型返回的答案类型和用量。测试不得把结果伪装成聊天回复。

角色选择开启后，任务详情可以显示“已由决策模型选择角色”。用户不需要查看完整请求体；调试信息应能展开查看角色 ID、选择概率和回退原因。

## 6. 产品验收

- 使用 `http://10.7.0.152:11434`、模型 `d3` 和无 API Key 配置时，能够成功调用 `/v1/systemone`。
- `noul`、`choice`、`score` 响应能够通过契约校验，并保留原始结构化字段。
- System One 连接不会出现在普通聊天模型选择器中。
- 开启角色选择后，明确的任务能够选择对应 Assistant 角色并进入该角色的现有执行链路。
- 角色选择模型不可用时，现有关键词路由或默认角色仍然可用。
- 用户手动指定角色时，不调用角色选择模型。
- 删除或切换角色选择模型后，配置状态与实际路由一致。
- 请求支持取消和超时，迟到结果不能覆盖新的任务路由。
