# Factory Droid Runtime 状态与归属

本文件实现 [FR-2 至 FR-9](./prd.md)，对应 [US-2 至 US-9](./user-stories.md)。

## 权威来源

| 对象 | 权威来源 | GoodBuddy 保存的内容 |
| --- | --- | --- |
| 当前执行、后台任务终态 | 所属 Droid 进程；远程场景由 Agent 托管 | 已确认状态及其原生任务关联 |
| 项目和会话归属 | 现有会话与任务存储 | projectId、conversationId、taskId、父请求关联 |
| 原生会话关联 | 现有 Runtime binding 存储 owner | provider、执行空间、配置标识、nativeSessionId |
| 待回答问题 | 发出请求的 Runtime 实例 | 原生请求与现有 questionId 的映射；可展示记录及草稿 |
| 输出 | 已有输出 backing owner 或 Droid 原生输出 | 有界预览和可读取引用，不维护两份可写全文 |

Todo 表示计划，后台任务表示正在执行或已经结束的工作，定时任务表示触发规则。
三者可以放在同一位置，但不能用 Todo 勾选结果推断进程状态，也不能为后台任务创建调度规则。

## 生命周期

一次前台 `run()`、一个会话、一个后台任务有独立生命周期。前台结束时释放发送队列的占用，
保留该会话的原生事件订阅、运行中任务及仍有效的问题。后台任务不依赖当前活动消息存在。

已有前台子任务仍遵循父请求结算规则；只有明确标记为会话级后台工作的任务可在父请求结束后
继续运行。接入需要同时修改 Main 路由、storage 投影、Renderer 终态处理与 Runtime 回收条件。

任务关联保留原始 parentRequestId、nativeSessionId、nativeTaskId/childSessionId、toolUseId
和配置实例归属。配置变化后，旧任务仍发往原 owner，直到结算；不能把旧问题发给新 Runtime。

## 状态规则

执行状态沿用现有任务领域：排队、运行、完成、失败、取消。等待用户回答通过已有问题关联
显示。停止请求中、连接中断和状态待确认是控制/连接状态，不伪造执行终态。

| 输入 | 行为 |
| --- | --- |
| 收到任务创建通知 | 建立原生关联，保存任务后发布界面更新 |
| 父回复完成 | 仅结算父回复；会话级后台任务和问题保持有效 |
| 发出停止操作 | 显示“正在停止”；收到 ACK 后等待任务终态或权威状态查询 |
| 停止失败或超时 | 保留已知执行状态，显示错误及重试入口，不显示“已取消” |
| 连接中断 | 显示“状态待确认”；保留最后确认的时间和状态 |
| 重连或加载 | 查询原生状态，更新摘要；不重发创建任务的 Prompt |
| 无法确认任务仍存在 | 显示无法恢复的原因；历史输出可读，不自动重新执行 |
| 任务终态到达 | 结算该任务，关闭它的未回答问题；新一轮前台请求不受影响 |

`killWorkerSession` 的 Mission 语义可能影响 orchestrator，禁止用它实现普通后台 Task 的
独立停止。`loadSession()` 会改变客户端当前会话，禁止在活动父流上用它轮询子任务。
普通后台任务的控制通道和终态查询须按[技术设计](./technical-design.md)完成验证。

## 停止与释放

| 用户动作 | 范围与结算 |
| --- | --- |
| 停止当前回复 | 取消当前前台 turn；已分离后台任务保留。若 native interrupt 会连带终止子任务，须先解决这一不一致 |
| 停止某个后台任务 | 只作用于指定原生任务及其自身后代；不得中断父回复或兄弟任务 |
| 切换会话/折叠顶部条 | 只改变展示，不取消执行 |
| 切换 Runtime 或模型配置 | 新请求使用新选择；旧后台任务仍由旧实例拥有，界面标识来源 |
| 删除会话 | 先释放其本地执行和问题，再按现有历史删除流程处理；失败须显示，不能留下无归属任务 |
| 正常退出桌面 | 本地任务停止并结算后关闭进程及存储；远程执行保留在 Agent，桌面断开 |

本地应用退出后继续运行属于持久 daemon 产品能力，本方案不承诺。原生会话历史恢复与
进程存活是不同事实；异常退出后的旧 running 记录先进入状态核对。

## 用户问答

`droid.ask_user` 到来时挂起对应 handler，转换为现有 `LiveAgentQuestion`。GoodBuddy 保存
questionId 到原生请求的对应关系，同时保留题目的 index 和原始 question 文本。

单选回答按实测结构返回 `answers: [{ index, question, answer }]`；跳过使用原生
`{ cancelled: true, answers: [] }`。多选的字符串编码须通过原生 schema/执行验证后确定，
不自行约定分隔符。用户答案不能转换成额外聊天消息来冒充原工具的返回值。

提交期间禁用重复提交；发送失败时保留草稿与问题。成功交付后才更新现有已回答记录。
任务结束、会话释放后，迟到答案显示已失效。后台问题改变对应任务的等待状态，不把已完成
的父消息重新标记为运行。普通工具权限沿用 GoodBuddy 统一执行规则，不与问答合并。
