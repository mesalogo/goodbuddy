# Factory Droid Runtime 产品需求

## 目标与范围

用户在 GoodBuddy 中使用 Droid 执行编程工作，沿用已有模型选择、工具能力、用户问答、
会话历史和任务查看方式。后台任务在主回复结束后仍可见、可查看结果，并可独立停止。
本文定义目标行为；实测范围见[验证进度](./progress.md)，界面行为见[界面设计](./ui-design.md)。

首版提供一个 `Factory Droid` Runtime，采用 GoodBuddy 管理的 BYOK 配置，固定启用 Droid
Airgap 环境变量。复用全局、项目、会话的模型继承规则。用户配置已安装的 Droid 可执行文件，
不增加第二个“Droid Airgap”provider，也不要求在两套设置中重复填写模型密钥。

普通 Factory 登录、订阅、云端会话以及用户全局 Droid 配置的导入不属于本方案。
本地 Runtime 和远程 Host 使用相同产品语义；远程支持须单独完成 Agent 接入与实机验收。
Airgap 启动设置不构成操作系统网络隔离保证。

## 安装与分发

Droid 不随 GoodBuddy 主安装包捆绑。优先检测和复用已有安装，也支持用户指定可执行文件。
未安装时提供可选的按需安装；内网场景支持管理员预装或本地文件导入。在线安装入口须在
确认分发授权、版本来源与校验信息后实施，不能默认跟随上游 latest。

同一执行 Host 上的多个项目共用一份二进制；会话配置与历史各自隔离。旧版本只有在没有
所属进程使用后才清理，用户自行安装的文件不由 GoodBuddy 删除。下载前分别显示下载量和
安装占用，二进制磁盘大小不能代替启动耗时或内存测量。

## 功能要求

| ID | 要求 |
| --- | --- |
| FR-1 | 在现有 Runtime 选择入口选择 Droid，显示可执行文件缺失、版本不兼容、模型不可用等具体原因；不回退到其他 Runtime 或模型 |
| FR-2 | 文本增量、工具活动、用量、错误、取消、多轮及恢复进入现有聊天流程；完整消息与增量不能重复渲染 |
| FR-3 | Droid Todo 进入现有待办条；后台子代理及后台命令单独显示在会话顶部，保留所属任务及原始调用关联 |
| FR-4 | 后台任务在主回复结束、开始下一轮、切换会话后保持可查；提供状态、输出、待回答问题及独立停止入口 |
| FR-5 | Droid 用户问题使用现有问答卡片；用户回答或跳过后交回原会话/任务，支持错误提示及草稿保留 |
| FR-6 | 停止当前回复、停止指定后台任务、释放会话、退出应用有明确且不同的影响范围；不得误伤其他会话 |
| FR-7 | 模型凭据由 Main 保管，能力遵循 GoodBuddy 分配；运行配置与用户全局 Factory 设置隔离 |
| FR-8 | 恢复以 Droid 实际会话和任务状态为准；失联显示状态待确认，不把本地历史中的 running 当作仍存活 |
| FR-9 | 远程任务由所属 Agent 管理，桌面断开不自动终止远程任务；恢复、输出和停止均路由到原 Host |
| FR-10 | 主安装包不含 Droid 二进制；支持已有路径、按需安装及离线导入，共享 Host 安装并保留使用中版本 |

## 交付判定

完整交付必须通过[用户场景](./user-stories.md)和技术设计中的验收矩阵。
创建后台任务成功不等于任务管理完成；停止请求收到确认不等于任务已经停止。
问答、增量已通过原生协议验证，产品 UI 尚未接入。普通后台任务的独立停止与终态同步是当前
待解决项，不应以隐藏按钮、改为停止整个会话或只提供演示数据来替代。
