# 界面设计

状态：工作区已有实现及 Electron 组件验收，完整应用验收见[进度记录](./progress.md)。遵循[统一界面设计](../../../UI-DESIGN.md)，实现 [FR-1 至 FR-9](./prd.md)，行为以[行为规则](./logic-design.md)为准。

## 模型配置

在现有图片模型连接表单提供“允许 AI 在会话中调用”。说明文字：“开启后，支持工具调用的聊天助手可使用此模型生成和编辑图片，编辑能力取决于图片协议。结果保存在发起请求的会话中。”复用共享 Switch，提供 `role="switch"`、键盘操作及可见焦点。

开启后提供“设为默认生图模型”，列表显示可调用和默认标识。关闭或删除默认连接时提示默认选择不可用，保留失效选择供改选，不自动指定其他模型。用户无需创建 Skill、搭建 MCP server 或重复填写 API 凭据；内部注入由 GoodBuddy 管理，不作为配置步骤展示。

## 能力与 Runtime 分配

复用设置中心“MCP / 内置 MCP”的列表与分配布局，增加“图片生成与编辑”行，标记“内置 · 自动管理”。这是 GoodBuddy 管理能力的展示入口，直连 Model 通过内部工具调用，外部 Runtime 通过内部 MCP 接入；不显示为用户另行添加的 MCP 或 Skill，也不混入 Runtime 原生能力清单。

该行按 L-1 展示直连文本 Model Runtime、本地 OpenCode、Continue、DeepSeek Harness 及 GoodBuddy Agent 远程适用 Runtime 的只读分配复选框。此图片能力采用用户已接受的自动管理规则，不沿用其他内置 MCP 的手动启停、可调分配或 DeepSeek Harness“暂不支持”状态。没有开启模型时仍保留整行及全部未勾选项，不能因目录为空隐藏。

持续显示说明“由图片模型的「允许 AI 在会话中调用」设置自动管理。”，并提供“前往图片模型设置”导航。该行不提供独立启用开关、保存分配、移除、编辑连接或凭据入口。运行就绪、无工具能力、配置或调用错误单独显示，不改变分配勾选。

分配复用共享 Checkbox 的方形视觉和原生语义，以 `checked` 表示派生值并使用 `disabled` 禁止鼠标、标签点击或键盘切换；仅在共享控件已有受支持的只读实现时采用该实现，不给原生 Checkbox 添加无效的 `readonly` 或自行添加 `aria-readonly`。每项保留 Runtime 标签和可访问名称，以 `aria-describedby` 关联自动管理说明。说明放在禁用控件之外，保持可读及辅助技术可访问；导航保持正常 Tab 顺序和可见焦点。窄窗口下分配项换行，保留标签、勾选状态、说明和导航。

## 会话入口

在现有聊天输入区以自然语言发起图片生成或编辑，本次指定模型也通过请求表达。复用上传附件和历史成果引用入口，输入区显示素材缩略图或文件名并允许移除。不新增会话级图片模型选择器、独立生成表单或视频入口。

未设默认时，助手提示本次指定可用模型，或到设置选择默认后重新发送；名称歧义先澄清。没有图片连接时提供现有模型设置入口。模型不支持编辑或素材缺失时保留输入，提示更换模型或重新选择素材。

直连文本、本地各 Runtime 和 GoodBuddy Agent 远程适用 Runtime 使用一致的图片操作与成果反馈。切换后可继续生成及编辑历史图；工具调用异常时显示具体原因，不宣称已提交。接入未完成的开发状态记录在进度文档，不能作为产品支持范围。

不支持工具调用时提示“当前聊天模型无法自动调用图片工具，可使用已有直连图片工作流”。Ask 下提示“生成或编辑图片需要 Execute 模式”，由用户切换，不自动切换。无视觉能力时说明无法直接查看图片，不妨碍按用户文字调用编辑工具。

## 图片卡片

复用现有图片成果展示，卡片就近显示实际模型、操作状态、成果或错误。提示词、适用参数和来源素材放在详情中；不显示密钥、认证头或供应商私有地址。活动记录与卡片使用同一操作标识。

完成后可预览、下载和“继续修改”。继续修改将成果加入输入区，用户填写修改要求；切换 Runtime 或重开会话后仍可使用。离开会话不取消操作，结果只出现在原会话。

进行中提供“取消生成”，与“停止回复”分开。取消、晚到结果和结果未确认的文案遵循 L-4。失败提供适用的“重新生成”“重新选择模型”或“重新选择素材”；重新生成由用户明确触发，并说明会发起新的模型请求。没有独立“重试保存”按钮。

“重新选择模型”进入已有模型连接设置；改变模型后，用户在新请求中明确指定。“重新选择素材”聚焦输入区并打开已有附件选择器，保留草稿和已有附件；空草稿填入原提示词及模型名称。历史成果仍使用“继续修改”加入引用并聚焦输入区。上述操作不自动发送请求，“重新生成”继续使用原操作的模型和输入。

卡片错误不重复弹全局通知；模型设置保存等非上下文反馈使用应用通知。状态使用文字，不能只靠颜色；状态变化通过适度的 `aria-live` 提示，避免逐秒播报等待时间。窄窗口操作可换行，图片不超过消息区宽度，模型长名称截断时保留完整可访问名称。复用的菜单关闭后焦点回到触发控件。
