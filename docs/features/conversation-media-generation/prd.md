# 产品需求

状态：设计草案。本文描述目标行为，不作为现有能力说明。

## 用户问题与范围

用户希望在文字会话中直接提出“画一张海报”“把上传图片的背景改成蓝色”“继续修改刚才的图片”，由聊天助手调用已配置的图片模型。切换聊天模型或 Runtime 后，应能继续生成、引用和编辑图片。

范围包括图片模型调用开关、全局默认与本次指定、文生图、已有协议支持的上传图片和历史图片编辑、成果保存、取消及状态反馈。支持直连文本 Model Runtime、本地 OpenCode、Continue、DeepSeek Harness，以及 GoodBuddy Agent 远程路径上的适用 Runtime；各路径的生成、编辑和切换均属于验收范围。

GoodBuddy 自动管理内部工具或 MCP 注入，复用模型连接与凭据。用户无需创建 Skill、搭建 MCP server 或填写第二套凭据。自动调用要求聊天模型支持工具调用；无工具能力时明确说明限制，用户可使用已有直连图片工作流。

不包含视频生成、模型训练、自动采购服务、通用文本指令执行器、批量渲染平台或应用退出后继续本地执行的承诺。不新增图片协议、会话级生成模型选择器、独立生成表单或通用恢复框架，也不安排视频交付计划。

## 功能需求

保留 FR-1 至 FR-9 编号。原需求中的视频部分移出范围，FR-2 的会话级选择由全局默认和本次指定替代，FR-7 的新增显式入口由已有直连图片工作流替代；下表为当前定义。

| 编号 | 要求 | 产品验收 |
| --- | --- | --- |
| FR-1 | 图片模型提供“允许 AI 在会话中调用”开关；新增和已有连接默认关闭，由用户主动开启；模型配置是图片能力启用与 Runtime 分配的唯一事实来源 | 至少一个模型开启时自动勾选全部支持 Runtime；全部关闭或删除时全部取消勾选；关闭或删除其中一个后若仍有开启模型，保持勾选并更新允许调用的模型目录；被关闭模型拒绝新操作，历史成果保留 |
| FR-2 | 支持全局默认和本次明确指定；编辑可沿用原成果模型 | 按[选择规则](./logic-design.md)解析并显示实际模型；失效或有歧义时提示，不静默换服务 |
| FR-3 | 在支持工具调用的聊天模型下，以自然语言生成和编辑图片 | 上传图片、历史图片及文生图均可经真实服务处理，保存后在原会话展示，活动记录可见 |
| FR-4 | 支持聊天模型、Runtime 及生成模型切换 | 切换后可发起新的生成和编辑；已提交操作固定原模型和原会话，不重复提交 |
| FR-5 | 支持上传素材、历史成果引用与连续编辑 | 重开会话及切换 Runtime 后可引用已保存原图；缺失素材或能力不足时保留输入并提示处理方式 |
| FR-6 | 生成操作独立显示状态，支持取消及人工重新生成 | 离开会话不取消；保存成功才完成；不虚构进度，不自动重试收费请求；重启后未完成操作显示结果未确认 |
| FR-7 | 遵循工作模式及模型能力边界 | Ask 不提交生成或编辑；无工具模型说明限制，可使用已有直连图片工作流，无需新增表单 |
| FR-8 | 图片作为会话成果保存 | 可预览、导出和重新打开，来源模型可追溯；无视觉聊天模型只接收文字事实及引用，不编造观察 |
| FR-9 | 本地及 GoodBuddy Agent 远程适用 Runtime 均支持图片工具；GoodBuddy 管理的图片生成与编辑能力及 Runtime 分配持续可见 | 分别完成真实生成、编辑、切换验收；分配复选框只读，不可手动切换；无开启模型时仍显示该行、未勾选状态、自动管理说明及模型设置入口；无独立能力启停、分配、移除或凭据编辑设置，用户无需维护 Skill 或 MCP server |

分配表示模型配置允许的调用范围。聊天模型不支持工具、Ask、Runtime 离线、配置错误或执行失败均单独说明，不取消配置分配的勾选；不保存可独立修改的能力启用或 Runtime 分配状态。具体推导与刷新规则由 L-1 定义。

## 产品验收

以[用户场景](./user-stories.md)验收。各 Runtime 分别记录真实工具往返、生成、上传图编辑、历史图编辑及切换结果，不能用单一路径成功代替其他路径。配置检查或工具注入成功不等于生成成功，成果必须可在会话中重新打开。

Runtime 接入细节和真实 Host 验证属于实施工作，未验证时如实记录未完成，不据此缩减 FR-9 的支持范围。
