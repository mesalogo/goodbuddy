# 执行规则

状态：当前源码规则；主要改造已落地，完整验收状态见[进度](./progress.md)。

## 请求与工具

L-1（FR-1、FR-2；US-01、US-04）：正常请求不存在工作模式维度。请求选择 Runtime、模型、执行空间和上下文后进入该 Runtime 的正常执行流程。工具支持不足不再映射为 Ask；纯文本请求仍可以完成。

L-2（FR-3；US-03）：工具由实际注册目录和已有能力配置提供。MCP 根据服务启用和 Runtime 分配接入，不按工具的读写标记筛选。读写标记仅用于说明。调用时检查工具确实来自已接入的服务，保留参数、会话资源和连接状态校验。

L-3（FR-2、FR-6；US-04、US-05、US-11）：原生工具不再使用 Ask 名单。上游需要 permission 配置或 ACP 回应时，由现有能力配置和真实调用身份生成；不使用全局 `workMode` 分支，也不把旧名单改名后保留。

| 条件 | 结果 |
| --- | --- |
| MCP 已启用、已分配，连接及资源可用 | 提供其已发现工具并按正常流程执行 |
| MCP 未启用或未分配 | 不注册该服务，调用不能绕过该状态 |
| 原生工具正常注册且无既有配置禁用 | 使用 Runtime 的正常执行能力 |
| 图片模型未允许会话调用或不可用 | 返回具体配置或可用性原因 |
| 所需知识库、图片引用、浏览器 Tab 不属于请求范围 | 返回业务范围错误 |
| 专用内部文本调用 | 不注入工具提供者或工具目录 |
| 请求已取消、超时或服务关闭 | 沿用对应生命周期处理 |

## 授权策略与内部任务

L-4（FR-7；US-10）：笔记分析、摘要、监督者和子代理综合结果使用其已有无工具构造路径。删除硬编码 `ask` 后仍须在执行边界保持无工具，不能只靠“不要调用工具”的提示词。该能力不向用户暴露为新模式。

L-5（FR-2、FR-7；US-17）：用户进一步确认删除“安全”设置分类及 `toolApproval` 策略。交互、通道、调度和委派不再通过该策略或产品工作模式阻止已启用工具；清除本地数据移到通用设置并保留确认。上传许可、覆盖选项和原生结构化提问按各自业务契约处理。

执行路径采用以下规则，不新增工具总开关或替代权限模式。

| 当前分支 | 本次处理与验收结果 |
| --- | --- |
| Controller / IPC 根据非 Execute 固定拒绝 | 删除该条件，无模式请求不再被此处拒绝 |
| 交互 Model 的 `toolApproval` | 删除字段、设置持久化及拒绝分支；启用工具正常执行 |
| 通道 Model 的工具策略 | 删除同一策略控制，不增加无人能响应的审批窗口 |
| 调度任务进入 ApprovalBroker | 删除一般工具审批等待；保留任务取消、超时和结构化问题处理 |
| 后台 Harness 自动允许 | 保留已有适配行为，仍需检查注册能力与参数 |
| 外部委派来源的固定拒绝 | 删除沿用只读委派的工具拒绝，仍使用已有能力、执行空间与资源范围 |
| 原生 Runtime 权限事件与问题 | 保持合法协议回应；删除产品模式拒绝，保留结构化问题与明确取消 |

原生协议需要权限答复时，对实际可用工具正常回应；该协议适配不恢复产品审批开关。远程通用 MCP 等缺失的传输能力仍不属于本次新增功能。

## 路由、队列与通道

L-6（FR-5；US-06、US-09）：任务、子代理和队列不再继承模式。智能路由保留开关、专家选择、团队选择和图片请求等已有条件，删除 Ask 条件。子任务继承真实执行空间与已授权上下文，不因删除模式获得未启用能力。

L-7（FR-8；US-07）：删除 `/ask`、`/execute`、`/exec` 及“对话/问答/执行”前缀的特殊解析。新消息按普通正文处理，保留文字，不剥离前缀，也不改变权限。仅含旧命令的非空消息按普通消息处理；空白消息仍按既有输入规则拒绝。通道帮助移除旧命令说明。

选择按正文处理可避免长期保留另一套命令兼容逻辑。历史存储正文不修改，用户明确要求“只解释、不修改”仍是应遵循的请求意图，但产品不再将其解释为系统级只读模式。

## 升级与恢复

L-8（FR-4、FR-9；US-02、US-13、US-16）：旧模式值不映射为常驻的新值；从指定结构中直接移除。SQL、JSON、导入、事件重放必须遵循同一转换规则。迁移只改应用拥有的模式元数据，不递归删除用户工具参数中的同名字段。

L-9（FR-6；US-11、US-12）：新请求使用无模式协议。旧 Agent 在现有版本协商处提示更新，不静默补 `execute`。已接受远程任务继续按操作身份恢复或明确报告无法恢复；不得为解决协议不匹配自动创建新操作或重新调用模型。

L-10（FR-9）：模式移除不重算已保存的操作摘要，不改远程序号、ACK、去重身份或计划执行时间。既有退出、停止、恢复和升级流程仍由所属功能管理。

## 完整性与未决事项

选择器、请求、执行、子代理、历史存储和远程链路均已纳入设计，无需再决定是否保留 Ask。MCP 的服务级设置沿用现状，不将逐工具开关作为本次前置条件。

剩余技术取证包括真实旧库中未声明 JSON 的形状、配套发布包升级与旧操作恢复、外部委派服务对无模式请求的兼容情况，以及旧工具策略在各生产入口的移除覆盖。真实 Host 的源码恢复证据与发布包升级验收分开记录，详见[迁移](./data-migration.md)与[进度](./progress.md)。
