# 产品需求

## 用户问题与目标

用户需要在会话中查找本机已有的 Obsidian 笔记，并将整理结果写回指定仓库。手动配置 Node、MCP 命令或 Obsidian 插件会增加首次使用步骤。接入应随应用提供依赖，支持先测试范围，再决定保存和启用。

## 功能需求

以下 ID 在后续实施中保持稳定。场景验收见[用户故事](./user-stories.md)，行为决策见[功能逻辑](./logic-design.md)。

| ID | 产品要求 |
| --- | --- |
| FR-1 | 首次使用及旧设置缺少 Obsidian 字段时默认关闭。保存范围、测试连接和启用是独立操作，不互相隐式触发。 |
| FR-2 | 默认 `vaultPath` 为空，访问本机已注册的全部仓库，包含未打开的仓库。用户可改选一个本机文件夹，也可恢复默认范围。 |
| FR-3 | 工具调用使用仓库 ID 定位。可用仓库超过一个时必须明确指定 `vaultId`；缺失或无效时返回错误，不按顺序、名称或最近使用情况选择写入目标。 |
| FR-4 | 提供 MCPVault 0.16.0 的全部 18 个上游工具及其参数能力。不得增加 Obsidian 专用只读设置、工具过滤或额外审批；应用现有 Ask/Execute 工作模式照常生效。 |
| FR-5 | MCPVault 及完整运行依赖随安装包交付，使用现有托管 Node，首次调用无需联网安装 npm 包，也无需用户安装系统 Node。 |
| FR-6 | 不依赖正在运行的 Obsidian、社区插件、REST 服务或 API 密钥。指定文件夹可绕过注册信息，不要求该文件夹已在 Obsidian 注册。 |
| FR-7 | 功能关闭时也可测试未保存的草稿。测试返回仓库名称、路径和上游工具数，不修改笔记、不保存范围、不启用功能。 |
| FR-8 | 范围无效、仓库不可访问、内置依赖缺失或工具执行失败时说明原因并保留草稿。取消文件夹选择不清空输入；会话调用取消后释放对应子进程。 |
| FR-9 | 沿用内置 MCP 的启用与 Runtime 分配方式。设置范围属于桌面端全局配置，具体会话仍受既有能力分配和工作模式约束。 |
| FR-10 | 提交保存范围、切换 Obsidian 开关或修改分配时，撤销此前含 Obsidian 的请求授权并取消其在途调用，避免继续使用旧范围或旧分配。应用关闭须等待活动工具清理；不回滚已经落盘的修改。 |

“离线”指本地 MCP 服务的启动和文件操作不需要下载依赖；模型服务是否联网由模型配置决定。工具返回的笔记内容会进入当前会话处理流程，不能将本地接入描述为模型推理也完全离线。

## 范围与非目标

本期接入原有仓库文件，不复制为 GoodBuddy 知识库，不提供同步服务、仓库管理器或 Obsidian 编辑器。附件相关能力按上游工具提供的范围开放，不承诺未包含在上游中的附件编辑能力。文件删除等参数沿用上游语义；上游参数校验不构成新增产品审批。

注册仓库发现不扫描整块磁盘，不推断最近活动仓库。接入支持直连模型、GoodBuddy 管理的本机 OpenCode 和 Continue；DeepSeek Harness 和远程执行路径保持不可用。远程 Host 仓库发现、跨设备同步和仓库迁移不在本期范围。

## 产品验收

发布前须完成[技术设计中的验证矩阵](./technical-design.md#验证与实施顺序)，并在[进度](./progress.md)记录真实结果。验收至少覆盖：关闭状态测试草稿、保存后重新进入设置、恢复全部仓库、多仓库明确选择、实际读取和写回、工作模式约束，以及安装包断网启动。

18 个上游工具按名称和参数契约逐项比对；加上仓库发现，共有 19 个共享工具。自动化验证分别覆盖注册 IPC、HTTP 网关和直连工具提供器，安装包及完整 Electron 界面仍单独验收。配置提交时还须验证旧授权立即失效、在途调用收到取消，以及网关销毁等待子进程清理完成。
