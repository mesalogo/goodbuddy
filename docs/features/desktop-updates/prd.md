# 桌面更新产品需求

## 用户问题与目标

现有设置页能识别系统和架构、列出新版本文件，但用户仍需打开网页寻找安装包。更新入口应直接准备正确的发布包，并明确区分下载、准备完成与安装完成。

## 范围

覆盖 Windows x64/arm64 安装版与便携版、macOS x64/arm64、Linux x64/arm64 的 AppImage、deb、rpm。沿用全局 `updateSource`，仅影响桌面应用更新，不改变模型、工具环境或远程 Agent 的下载设置。

首版使用完整发布包。应用更新需要退出；不承诺运行中任务跨重启恢复，不提供数据库降级，不自动更新远程 Agent，不默认在退出或空闲时安装。

## 需求与验收

| 编号 | 需求 | 产品验收 |
| --- | --- | --- |
| FR-1 | 发现新版本时显示下载更新入口 | 用户无需去网页选择对应系统和架构；安装格式无法可靠判断时明确选择 |
| FR-2 | 下载固定版本的发布包 | 源、版本、大小和 SHA-256 在下载开始时固定；失败不偷偷切源 |
| FR-3 | 提供进度、取消、失败重试 | 关闭设置页不取消后台下载；取消结算后可重试，失败不影响旧版本使用 |
| FR-4 | 下载完成后才提供安装操作 | 字节数和 SHA-256 不匹配时不可安装；界面说明下一步是否会退出 |
| FR-5 | 支持重启更新与系统安装交接 | NSIS、便携版、macOS、AppImage 按对应机制更新；deb/rpm 经系统安装，保留必要的授权交互 |
| FR-6 | 提供自动下载设置 | 新旧配置默认关闭；启动检查开启时，检查出新版本后按设置自动准备，绝不自动重启 |
| FR-7 | 保护正在进行的工作 | 保存、活动工作检查和正常退出成功后才安装；清理失败不启动安装器 |
| FR-8 | 保持安装方式与用户数据 | 安装版沿用安装位置；便携版保留 data 与用户附加文件；更新不清空用户配置 |
| FR-9 | GitHub 与镜像发布一致 | 两个源对应同一版本的相同字节；新版本指针仅在文件集完整后发布 |
| FR-10 | 管理更新文件完整生命周期 | 失败、取消、损坏包及时清理；启动回收已安装版本和遗留半包；保留可重试候选并提供手动清理；占用或权限失败可见且不无限重试；仅处理所属更新文件 |

完成标准为真实打包应用通过 UI 下载并完成升级，再启动新版本；单元测试或构建成功不能代替安装验证。各平台未验证项必须记录在实施记录中。
