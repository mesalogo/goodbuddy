# 桌面更新行为规则

## 状态与转换

更新检查和安装包准备属于同一更新领域。Main 持有当前结果和准备状态，Renderer 订阅快照。

| 状态 | 可执行操作 | 后续状态 |
| --- | --- | --- |
| idle / available | 检查、下载 | available、downloading、error |
| downloading | 取消 | verifying、available、error |
| verifying | 等待或取消 | ready、available、error |
| ready | 重启更新或打开安装包、重新检查 | restarting、available、error |
| restarting | 校验、保存确认、关闭清理与安装交接 | 准备失败回 ready；校验失败进 error；交接成功退出旧进程 |
| error | 重试、查看下载页面 | downloading 或 available |

下载和校验未结算前不能启动第二次下载；取消先请求终止，再等待文件关闭和清理。迟到的结果不得替换新操作状态。（FR-2、FR-3；US-5、US-6、US-11）

## 产物选择

按实际运行架构选择发布目标。Windows 以便携标记区分 ZIP 与 NSIS；macOS 自动更新使用 ZIP；Linux 优先识别 AppImage，再识别系统软件包归属。无法判断格式时让用户选择，不能猜测或直接把便携版转换成安装版。（FR-1、FR-8；US-1 至 US-4）

源、版本、文件名、大小和 SHA-256 在操作开始时冻结；URL 由 Main 从已校验发布信息生成。设置切源只影响后续操作；当前下载继续使用已选源，界面保留该信息。不跨源自动重试。（FR-2、FR-9；US-5、US-11）

## 准备与安装

达到清单字节数并通过 SHA-256 校验后才进入 ready。相同版本的文件可在重新校验后复用；不以缓存文件名或文件存在作为校验成功。（FR-4；US-7）

自动下载与启动检查是独立设置；自动下载不触发检查、不代表允许自动安装。显式检查发现新版本时同样遵守自动下载设置。（FR-6；US-8）

重启更新须经过工作状态检查、未保存内容处理和现有退出清理。只有确认清理完成才交接安装；关闭窗口到托盘不算退出。系统包打开动作仅表示已交给系统，不表示安装成功。（FR-5、FR-7；US-9、US-10）

准备阶段未通过时继续使用当前应用；已进入关闭清理后失败时不启动安装器，显示错误并退出旧进程，保留原版本供重新打开。NSIS 的启动成功和新版程序已经安装完成是两个不同事实，客户端不把创建安装器进程显示为升级成功。

## 完整性评估

产品决策已明确。技术待验证项包括 Windows 完整安装包和提权、macOS 签名条件、Linux 包格式检测以及便携替换辅助程序。验证缺口归实施记录所有，不改变上述行为要求。

## 缓存生命周期（FR-10；US-12 至 US-14）

| 场景 | 清理规则 |
| --- | --- |
| 下载失败或取消 | 等待文件句柄和 Worker 释放后删除本次半包；取消或下载失败也删除本次未能确认为成功的目标文件 |
| 打开或重启前发现大小、SHA-256 不符 | 删除损坏完整包，回到可重新下载的错误状态；读取失败和完整性不符分别处理 |
| 下载成功、尚未安装 | 保留当前候选；下一次下载先清理其他所属文件，当前候选与新清单一致时重新校验并复用；其他旧文件删除失败时保留警告，仍允许下载新包 |
| 保存检查未通过或安装器启动失败 | 保留完整候选供重试；不因准备失败清空有效下载 |
| 新版本启动 | 首屏加载后删除版本不高于当前应用的包，以及任意版本的遗留半包；更高版本候选保留 |
| 曾经使用的更新缓存位置 | 同时检查 desktop-updates 顶层的规范包文件，按相同规则处理；不递归遍历其他目录 |
| 文件已交给安装器或文件管理器 | 本次进程内冻结包，禁止清理与再次下载；重启后按实际版本和占用情况回收 |
| 文件被占用或没有删除权限 | 继续清理其他可清理文件，保留失败原因；启动/手动清理失败后仅在 30 秒后重试一次，若有新操作则跳过；仍失败等待后续启动、下载或手动清理 |
| 用户主动清理 | 空闲时清除所属候选和半包，重置 ready 状态；运行中的下载、校验、重启和已交付文件不能被清理 |

所属文件必须位于更新服务的缓存位置并符合 GoodBuddy 发布包命名；未知文件、子目录、链接和当前进程的可执行文件/AppImage 路径保留。清理只读取本地文件，不切换下载源或联网。下载失败与清理失败同时出现时保留两个原因，不用清理错误覆盖原始下载错误。NSIS 自身的安装临时目录由安装器管理，应用不扫描系统临时目录或用户下载目录。
