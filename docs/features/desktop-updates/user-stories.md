# 桌面更新用户故事

| 编号 | 场景与验收 | 需求 |
| --- | --- | --- |
| US-1 | 已安装 Windows 用户检查到新版本，点击下载后取得同架构安装包；准备完成后主动重启，仍从原安装位置启动，配置保留 | FR-1、FR-4、FR-5、FR-8 |
| US-2 | 便携用户目录带 data 和自建文件；更新后仍使用原 data，自建文件保留，旧应用废弃文件被清理 | FR-5、FR-8 |
| US-3 | macOS 用户在已安装应用中更新；无需自行拖动文件即可完成受支持的自动更新路径，签名与启动检查通过 | FR-5、FR-8 |
| US-4 | Linux 用户更新 AppImage 或软件包；匹配当前格式，权限不足时说明系统安装步骤 | FR-1、FR-5 |
| US-5 | 用户选择镜像后下载，网络失败；错误关联到本次下载，重试仍使用选定源，切换来源需开始新操作 | FR-2、FR-3、FR-9 |
| US-6 | 下载时离开设置再返回，进度仍在；取消后再下载，不混入旧操作的进度或文件 | FR-3 |
| US-7 | 下载损坏或发布大小不符；界面显示校验失败，不出现可执行安装入口 | FR-4 |
| US-8 | 新用户和旧配置首次使用；自动下载关闭。用户开启后重启应用，检查到更新即准备，但不自动退出 | FR-6 |
| US-9 | 用户有任务或未保存编辑时请求更新；提示稍后处理，不强杀工作。退出清理失败时不执行安装 | FR-7 |
| US-10 | 全局安装需要管理员权限；系统显示正常授权提示，拒绝授权后旧版仍可启动，可再次尝试 | FR-5、FR-8 |
| US-11 | 下载期间发布又一个版本；当前操作始终使用已经选定的版本和校验信息 | FR-2、FR-9 |
| US-12 | 下载中应用异常退出；下次启动回收半包，完整候选重新校验后可以复用；用户明确清理时删除候选 | FR-3、FR-4、FR-10 |
| US-13 | 新版本已启动但安装器仍占用缓存文件；先保留被占用文件并提示，一次延后重试后仍失败则等下次启动或用户操作 | FR-10 |
| US-14 | 更新缓存里有旧版包、旧缓存位置文件、个人文件或当前运行的 AppImage；仅清理可识别的所属闲置文件，保留个人文件、子目录及运行文件 | FR-10 |

开发运行环境不替换源码目录或当前运行的生产安装。实际安装验证使用独立安装目录与独立用户数据。
