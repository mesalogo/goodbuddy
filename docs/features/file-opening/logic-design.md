# 文件打开与会话渲染规则

本表定义目标行为；实际能力见[实施进度](./progress.md)。对应需求与场景见
[PRD](./prd.md)。格式表只在此处维护。

## 内容对象与入口（FR-FO1、2、4）

先区分正在展示的对象，再选择渲染方式。“出现在会话里”描述展示位置，不代表内容就是
消息正文；会话中的附件和文件链接仍然引用实际文件。

| 对象 | 示例 | 判断依据 | 处理规则 |
| --- | --- | --- | --- |
| 消息正文及代码块 | Agent 直接回复 Markdown 或 HTML | 消息角色、完成状态、内容语法及设置 | 使用消息渲染规则，不按文件扩展名分发 |
| 会话中的文件引用 | 上传的 `报告.pdf`、回复中的 `index.html` 文件链接 | 附件资源 ID 或项目与路径 | 先展示引用；打开或明确预览时读取对应文件 |
| 实际文件内容 | 工作区 `README.md`、附件 PDF 的字节内容 | 文件身份、类型、解码结果 | 按下表选择阅读方式，入口可来自工作区或会话 |

会话附件和项目文件有不同的存储归属，但同类型文件可以共用阅读器。文件的内容不会因为
入口在会话里就成为 Agent 消息；消息中直接出现的 HTML 也不会自动成为 HTML 文件。

## 文件类型表（FR-FO1、2、3）

本表仅适用于实际文件及其引用，不定义普通消息正文的渲染方式。“会话中的文件展示”
描述文件引用或文件预览。缩略图、摘要仅在已有结果或用户请求预览时加载；普通链接不
自动变成全文预览。已作为图片附件展示的内容沿用图片附件规则。

| 类型 | 扩展名或名称示例 | 文件默认目标 | 会话中的文件展示 | 可选方式 |
| --- | --- | --- | --- | --- |
| Markdown | `.md`、`.markdown` | 右侧正文预览 | 文件卡片；明确预览时渲染文件正文 | 源码 |
| HTML | `.html`、`.htm` | 右侧浏览器 | 文件卡片；文件内容内嵌预览的触发与设置归属待定 | 源码 |
| 纯文本 | `.txt`、`.log`、README、LICENSE | 右侧文本预览 | 文本片段或文件卡片 | 本机系统打开 |
| PDF | `.pdf` | 右侧文档阅读器，分页、缩放 | 文件卡片，可带首页缩略图 | 已有解析正文、本机系统打开 |
| Word | `.docx` | 右侧文档阅读器，保留可支持的版式 | 文件卡片，可带摘要 | 已有解析正文、编辑、本机系统打开 |
| Excel | `.xlsx` | 右侧表格阅读器，切换工作表 | 文件卡片，按需预览表格 | 编辑、本机系统打开 |
| PowerPoint | `.pptx` | 右侧幻灯片阅读器 | 文件卡片，可带封面 | 已有解析正文、编辑、本机系统打开 |
| 旧 Office | `.doc`、`.xls`、`.ppt` | 文件信息；转换能力可用时明确提供转换后预览 | 文件卡片 | ShareServer 转换后编辑、另存为现代格式、本机系统打开 |
| 开放文档、富文本 | `.odt`、`.ods`、`.odp`、`.rtf` | 有对应阅读器时阅读，否则文件信息 | 文件卡片 | 本机系统打开 |
| 表格数据 | `.csv`、`.tsv` | 右侧表格预览 | 文件卡片或明确请求的表格预览 | 原文 |
| 结构化数据 | `.json`、`.yaml`、`.yml`、`.toml`、`.xml` | 右侧源码预览 | 文件卡片；明确预览时显示文件源码 | 本机系统打开 |
| 源码、配置 | `.ts`、`.tsx`、`.js`、`.py`、`.css`、`.ini`、Dockerfile 等 | 右侧源码预览 | 文件卡片；明确预览时显示文件源码 | 本机系统打开 |
| 图片 | `.png`、`.jpg`、`.jpeg`、`.webp`、`.gif`、`.bmp`、`.svg` | 右侧图片预览 | 图片预览 | 本机系统打开 |
| 音视频 | `.mp3`、`.wav`、`.mp4`、`.webm` 等 | 播放器可用时播放，否则文件信息 | 媒体卡片，不自动播放 | 本机系统打开 |
| 压缩包及其他二进制 | `.zip`、`.7z` 及未识别类型 | 文件信息 | 文件卡片 | 本机系统打开 |

编辑、转换和解析正文选项仅在对应能力或结果可用时提供。此表不承诺 Office 版式完全
一致，也不授予阅读器编辑权限。具体阅读保真度由真实文件验收记录说明。

### 在线编辑的服务条件

Office 在线编辑依赖所连接 ShareServer 实际提供的 Office 能力，不是客户端或任意
ShareServer 的默认能力。工作区、会话生成文件链接、成果文件和附件使用同一文件引用规则；
普通打开仍走阅读分支，不自动上传。显式选择在线编辑后复用共享连接：未配置时保留文件引用
并引导配置；服务不可达、未启用、格式不支持分别报告原因；检查通过后才读取并上传编辑副本。
远程项目文件始终通过所属 Agent 的 Workspace 通道读取与回写，不将远程路径当作本地路径。

服务条件与当前契约由 [Office 技术设计](../office-document-editing/technical-design.md#6-文件与保存)
维护。服务器持久化成功与写回源文件是两步；不可覆盖的附件使用另存为。
旧格式由 ShareServer 转换后编辑，不能将现代格式字节写进旧扩展名文件；本地和远程原件均保留。

## 入口与选择顺序（FR-FO1、4）

1. 先确定来源：项目文件、会话附件、消息内容或 HTTP(S) 地址。消息正文没有文件身份。
   附件保持其资源引用；远程路径始终携带 Host 和项目身份。
2. 用户明确选择“源码”“浏览器”“系统打开”等方式时，执行该方式并检查当前能力。
   Git 中普通点击保留 Diff 语义；“查看当前文件”才进入文件分发。
3. 普通文件点击按类型表选择默认目标，再判断当前平台、Host 和阅读器是否支持。
   HTTP(S) 链接沿用浏览器规则，不按 URL 后缀当作本地文件。
4. 能力不可用时显示文件信息、原因和可用操作；HTML 可以提供源码作为显式替代入口，
   不把源码页面标成网页已打开。

扩展名大小写归一化，扩展名缺失时可结合已知文件名和可信 MIME 判断候选类型。
读取后由实际解码器或阅读器校验；内容与类型不符时报错，不能把任意二进制强行按 UTF-8
展示，也不能把普通文本中的标签自动升级成 HTML 文件。

## 会话内渲染（FR-FO2）

### 消息内容

文件打开目标和会话渲染条件独立判断。本规范不新增通用渲染开关或逐扩展名设置。
普通 Markdown 消息沿用消息排版，Markdown 代码块保持源码。

HTML 的识别、消息角色、完成状态、设置开关及执行权限统一引用
[会话 HTML PRD](../conversation-html-rendering/prd.md)。该规范包含已完成 Agent 回复中的
`html/htm` 代码块自动预览；不得套用普通代码块规则将其改为默认源码。
关闭会话 HTML 渲染保留源码，文件打开行为不受影响。HTML 权限不在本文件重复定义。

### 会话中的文件引用与文件内容

会话 HTML 开关目前定义的是消息内容渲染，不能据此认定它也控制 HTML 附件或项目文件的
内嵌预览。HTML 文件是否增加会话内预览、何时加载及是否复用该开关，作为待定产品项，
在明确前只定义文件卡片与主动打开，不新增自动渲染行为。

文件链接不会因后缀是 Markdown 或 HTML 就自动读取全文。明确展示的文件预览卡片控制
可见高度并支持展开；有文件身份时提供右侧打开操作。消息 HTML 转成实际项目文件属于
独立保存动作，不由渲染隐式执行。SVG 作为图片加载，不插入消息 DOM。

## 阅读模式与状态（FR-FO3、4、5）

原件阅读、解析正文和编辑模式分别标识。阅读 PDF 或 Office 文件不触发自动 OCR、上传
解析或源文件写入；用户请求解析或编辑时交给所属功能处理。

打开前记录来源列表状态；加载成功后显示对应内容，失败后保留返回入口。返回恢复目录、
展开、滚动、选择和已有筛选；打开浏览器时也应保留此来源。项目或文件切换会使旧读取失效。
刷新失败保留上次内容，并标注错误；首次失败显示原因与重试。文档分页和文本分段加载需
表明已加载范围。大型内容按需读取，性能预算引用[性能原则](../../architecture/performance-principles.md)。

本机与远程采用同一默认类型规则，能力判断分别进行。远程断连不能当成不支持格式；
远程文件不能直接传给本机系统打开。下载后打开仅在存在对应功能时提供。

## 完整性与待定事项

规则覆盖默认打开、显式替代、会话展示、Git 上下文、返回、失败、取消及远程来源，
验收对应 US-FO1 至 US-FO11。尚待实施方案确定的是 HTML 文件资源通路、文档阅读器选型
及各格式保真度。另需确定 HTML 文件内容的会话内嵌预览策略，不与已有消息 HTML 渲染
混为一项能力。新增文件类型须补充格式行和验收场景。
