# 文件打开与内容预览技术设计

本文规定后续实现的接入边界，本轮不创建代码接口或选择新的阅读器依赖。
产品行为以[打开规则](./logic-design.md)为准，遵循
[性能原则](../../architecture/performance-principles.md)和
[功能维护约束](../../development/agent-feature-maintenance.md)。

## 分发职责

消息正文先走消息渲染链路；只有实际文件引用进入文件类型分发。会话文件引用解析为附件
资源或项目路径后再读取，不以会话入口替代来源身份。文件内容的内嵌预览需要显式上下文，
不得直接复用消息 HTML 的自动识别来触发读取或执行。

为文件列表、项目文件链接和附件打开入口复用类型解析与打开目标选择。
输入应保留来源身份、文件名、可用 MIME、显式操作及当前环境能力；输出区分浏览器、
正文、源码、图片、文档、表格、媒体与文件信息。先使用简单的共享类型表和选择函数，
无需插件注册系统或新增持久化设置。

Renderer 承担交互和来源列表状态，Main 沿用既有 IPC 校验及 OS 操作。
项目文件通过 WorkspaceAccess 读取，远程通过对应 Agent；会话附件复用已有资源访问链路。
文档解析继续由文档处理模块承担，编辑调用 Office 功能，不在打开分发中另建解析器。
阅读器按需加载，不因渲染文件列表就预读全部文件。

## 当前接入点与缺口

- `WorkspaceChangesService.readFile` 当前按扩展名区分图片、Markdown、JSON 和纯文本。
  后续应与统一类型判断对齐，保留分页与取消语义。
- `RightAssistantSidebar` 当前负责图片、Markdown 和纯文本显示；新增路由应保留返回状态，
  并沿用当前组件和 store 边界，不把类型分支继续堆入 App。
- `browser-url-policy.ts` 当前只接受 HTTP(S)。HTML 文件到浏览器的完整通路尚需设计，
  包括相对 CSS、图片、JS 资源、刷新、源文件身份、关闭释放和远程资源访问。
  不能仅把文件路径交给现有 navigate 接口即宣称完成。
- 会话 HTML 的加载协议、脚本与网络权限沿用
  [专属技术设计](../conversation-html-rendering/technical-design.md)。消息 HTML 和项目文件
  的资源来源不同，接入时分别验证，不推断其协议已支持工作区文件。
- 文档阅读方案可评估 [Office 功能目录](../office-document-editing/README.md)下的本地预览 Demo，
  正式接入须验证 Desktop UI、资源读取、远程文件及真实文件保真度。Demo 通过不等于生产可用。

## 后续实现与验证

按后续授权范围实施统一分发与具体阅读器。每次新增格式同步维护规则和进度，不要求
一次实现格式表中的全部阅读器。生产验证至少覆盖文件列表和聊天链接的同路由、显式源码、
Git Diff、来源恢复、刷新失败和项目切换；涉及远程时验证真实 Host 通路。

会话渲染核对开关、用户消息、推理、流式与完成状态，保留 HTML 代码块的既有行为。
Office/PDF 验证分页、工作表、幻灯片、损坏文件和原件不被修改，记录未支持特性。
大文件验证按需读取与界面响应，性能数值及过程要求不在本目录另行定义。
