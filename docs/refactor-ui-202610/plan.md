## 1. 目标

评估 Penguin UI Gallery 对 GoodBuddy 的可借鉴做法，形成一份有证据的 UI 重构顺序。计划关注信息架构、页面壳层、组件状态、主题令牌、复杂工作台密度和响应式行为。本阶段只完成调研和计划，不编写产品代码。

## 2. 调研结论

### 2.1 参考站点提供的有效做法

参考站点把真实应用、界面索引、基础令牌、组件画廊和字体信息放在同一个可操作页面中。页面支持切换主题、明暗模式、字号、字体和语言，切换结果直接作用于嵌入的应用示例。

可借鉴的内容有：

- 以“对话、工作台、资源、度量、系统”组织应用入口，减少用户理解一级导航的成本。
- 为工具运行中、思考中、流式输出、待审批、空状态、加载和错误等状态提供可点击的样例。
- 用同一套页面展示框架、组件、视觉令牌、字体排印、密度、焦点和动效，方便检查跨页面一致性。
- 通过轻边框、低饱和侧栏、单一强调色和有限阴影控制复杂页面的视觉噪声。
- 在应用索引中同时覆盖列表、详情、表格、图表、文件、设置和对话，验证组件在不同任务中的组合方式。

### 2.2 GoodBuddy 已有基础

当前实现已经覆盖参考站点建议的大部分基础能力：

- [App.tsx](../../src/renderer/src/App.tsx) 已组织聊天、魔法笔记、知识库、智能心跳、本地推理、设备共享、远程主机、活动记录和设置等工作区。
- [WorkspacePrimitives.tsx](../../src/renderer/src/WorkspacePrimitives.tsx) 已提供 `PageShell`、`PageHeader`、`PageTabs`、`SegmentedControl` 和 `ScopeBadge`。
- [styles.css](../../src/renderer/src/styles.css) 已定义表面、文字、边框、强调色、状态色、间距、圆角、字号、字体和动效令牌。
- `ConversationTaskStrip`、消息活动块、右侧助手栏和活动记录已经承载任务、工具、审批和运行结果等状态。
- [UI-DESIGN.md](../../UI-DESIGN.md) 已规定页面壳层、信息层级、主题、可访问性和响应式原则。

### 2.3 当前差距与判断

GoodBuddy 的能力范围比参考站点的演示应用更复杂，直接复制其导航或页面布局会掩盖项目、任务、Runtime 和工具状态。后续重构应保留 GoodBuddy 的页面壳层和任务语义，优先处理以下差距：

- 一级导航已有多个应用入口，但缺少面向用户任务的稳定分组和分组标题。
- 状态能力分布在聊天、任务条、右侧助手栏、通知和活动记录中，需要统一状态摘要、图标、文案、耗时和展开行为。
- 现有设计令牌已经完整，但缺少一个集中展示真实组件和真实状态的 UI Gallery，改动后只能分散检查页面。
- 知识库、智能心跳、魔法笔记和右侧助手栏信息密度较高，需要以主任务优先原则检查标题、范围、操作、筛选和详情的层级。
- 参考站点把字号、字体和主题作为可见的系统能力；GoodBuddy 已支持浅色、深色和磨砂特效，字号、密度和跨页面主题回归仍需补充基线。

### 2.4 顶部会话标题建议

建议把聊天顶栏的标题组织成两层：第一行显示会话标题，第二行显示当前项目和必要的来源范围信息。当前实现中会话标题、分支或通道标记和 `ScopeBadge` 都处在同一个 `58px` 顶栏行内，项目范围会与会话标题争夺横向空间，也使标题组显得偏高、偏重。

建议保持顶栏总高度不变，把项目名称作为会话标题下方的紧凑上下文行，而不是增加顶栏高度。项目切换仍由左侧 `ProjectSwitcher` 完成，顶栏中的项目只承担当前范围提示，并保留截断、悬停说明和无障碍名称。分支标记、远程通道标记等状态继续靠近会话标题，但不再把项目名称与它们放在同一视觉层级。

该建议进入批次 2 的信息架构评估，实施前需要用长会话标题、分支会话、远程会话、项目名过长和窄窗口截图确认。非聊天页面继续使用单行顶栏。

## 3. 整体实施计划

### 3.1 实施原则

整体重构按“先建立证据，再统一共享表达，最后调整页面组合”的顺序推进。每一阶段都要有明确的页面范围和完成证据，完成一阶段后再决定是否进入下一阶段。现有功能语义、任务状态、项目范围和 Electron 窗口行为优先保持稳定。

### 3.2 阶段总览

| 阶段 | 主题 | 主要内容 | 进入条件 | 交付物 |
| --- | --- | --- | --- | --- |
| 0 | 基线与范围确认 | 页面清单、截图、状态场景、性能关注点和未提交改动边界 | 调研结论已形成 | UI 基线包、差异清单、页面优先级 |
| 1 | 共享 UI 与状态语言 | 页面壳层、标题层级、状态活动块、通知、空状态、加载和错误表达 | 阶段 0 的目标页面和状态已固定 | 共享组件调整方案、状态矩阵、组件回归清单 |
| 2 | 应用框架与信息架构 | 主导航分组、项目切换、会话标题、会话列表、右侧助手栏入口和窄窗口路径 | 阶段 1 的共享表达稳定 | 导航调整方案、聊天框架改动、窄窗口验收结果 |
| 3 | 复杂工作区整理 | 知识库、魔法笔记、智能心跳、活动记录和远程主机的标题、范围、操作、筛选和密度 | 阶段 2 的入口和状态语义稳定 | 各工作区页面调整、主从布局和密度验收结果 |
| 4 | UI Gallery 与视觉回归 | 真实组件画廊、主题、字体、密度、焦点、动效、响应式和截图回归 | 阶段 1 至 3 的生产组件边界明确 | 内部 UI Gallery、回归场景和文档更新 |
| 5 | 收口与发布检查 | 清理重复样式、修正文档、确认性能和无障碍回归、整理未完成项 | 目标页面全部完成或明确延期 | 变更清单、验证报告和后续事项 |

### 3.3 阶段 0：基线与范围确认

- 固定聊天、知识库、魔法笔记、智能心跳、活动记录、远程主机和设置的主要页面基线。
- 覆盖浅色、深色、磨砂特效、窄窗口、右侧助手栏展开和执行中任务。
- 为长标题、长项目名、分支会话、远程会话、无项目、空数据、无结果、失败和审批等待建立场景清单。
- 标记当前工作区已有的未提交修改，后续不把它们误判为本次重构结果。
- 按用户影响、跨页面复用程度和实施风险给页面排序。

完成标准：每个目标页面都有入口、状态条件、截图或可复现步骤、涉及组件和验收责任。

### 3.4 阶段 1：共享 UI 与状态语言

- 以 `UI-DESIGN.md` 和现有 `PageShell`、`PageHeader`、`PageTabs`、`SegmentedControl`、`ScopeBadge` 为共同基础。
- 统一标题、说明、范围、主操作、次要操作和页面状态的层级。
- 统一工具运行、思考、流式输出、审批、成功、失败、取消、超时、重连和部分输出的摘要与详情。
- 统一活动块、任务条、通知和活动记录之间的显示边界，避免重复展示同一事件。
- 补齐空状态、无结果、加载、只读、权限不足和错误恢复的组件场景。

完成标准：跨聊天、右侧助手栏和活动记录使用一致的状态结构；主题、焦点、键盘和减少动态效果检查通过。

实施状态：已完成运行记录状态徽标和会话任务条的状态文字与状态点。工具活动块、审批卡、应用通知和右侧助手栏之间的显示边界仍待继续核对。

### 3.5 阶段 2：应用框架与信息架构

- 保持主导航为连续入口列表，重点检查当前项、入口顺序和项目／会话上下文，不增加工作区左侧分组标题。
- 保留项目切换器作为项目切换入口，区分项目范围提示和项目管理操作。
- 调整聊天顶栏的会话标题和项目范围层级，作为本节后面的首批实施项。
- 检查会话列表的搜索、置顶、分支、任务展开、未读和删除操作是否与主导航层级一致。
- 检查右侧助手栏的入口、打开关闭、返回和窄窗口行为。

完成标准：用户能从侧栏识别当前页面、当前项目和当前会话；窄窗口仍能完成导航、搜索、项目切换和返回。

实施状态：已完成聊天顶栏两层标题、运行记录状态徽标和会话任务条状态文案切片；工作区左侧菜单保持连续列表，不采用视觉分组标题。当前实现保留原有入口顺序、路由、项目切换、会话操作、任务选择、状态筛选和右侧助手栏行为；相关 ActivityPanel 与 ConversationTaskStrip 的 35 个用例和类型检查通过。尚未完成窄窗口 Electron 截图基线和整体阶段验收。

### 3.6 阶段 3：复杂工作区整理

- 知识库：检查主从布局、范围徽标、来源、检索状态、图谱和文档详情的层级。
- 魔法笔记：检查笔记列表、画布、来源、待办和保存状态的关系。
- 智能心跳：检查监督工作台、故事线、建议、运行设置和执行状态的密度。
- 活动记录：检查筛选、分页、统计、详情和错误状态的阅读顺序。
- 远程主机：检查连接状态、机器列表、详情工具栏、添加流程和失败恢复。
- 每个工作区只保留一个主要视觉焦点，次要操作进入共享菜单、页签或筛选工具栏。

完成标准：页面标题、范围、状态、筛选、主操作和主内容顺序稳定；长表格、日志和来源详情在页面内部滚动。

### 3.7 阶段 4：UI Gallery 与视觉回归

- 建立只复用生产组件的内部 UI Gallery，按页面壳层、控件、反馈、内容、数据和状态分类。
- 用真实状态覆盖按钮、输入框、选择器、页签、分段控件、徽标、通知、对话框、空状态、加载、工具活动块、Markdown、代码块、表格和文件行。
- 统一检查浅色、深色、字号、字体、减少动态效果、键盘焦点、中文长文本和窄窗口。
- 将 Gallery 场景和关键页面截图作为后续视觉回归基线。

完成标准：共享组件的主要状态可以集中查看，且无需为 Gallery 建立第二套生产样式。

### 3.8 阶段 5：收口与发布检查

- 清理被共享组件替代的页面专属样式，保留有明确业务语义的例外。
- 检查主题令牌、字体、圆角、间距、焦点和动效是否继续由统一设计系统管理。
- 对涉及大列表、KeepAlive、滚动容器和顶栏磨砂的改动补充性能或行为证据。
- 更新 `UI-DESIGN.md`、受影响的功能文档和本计划中的状态，不把设计意图写成已实现事实。
- 汇总完成项、延期项、外部依赖和仍需产品决策的事项。

完成标准：代码、真实用户路径、测试、截图和文档状态一致，未完成范围有明确记录。

### 3.9 CSS 拆分评估

当前 `src/renderer/src/styles.css` 约 20,072 行、437 KB，是 Renderer 中最大的样式文件。仓库已经有 22 个按模块拆分的 CSS 文件，且多数通过组件自身导入，例如应用中心、远程主机、魔法笔记、终端、任务中心和外部知识。这说明模块化方式已经被项目采用，剩余问题主要集中在全局文件承载范围过大。

拆分的收益：

- Agent 可以在较小的模块文件中定位页面和组件样式，减少无关上下文。
- 页面改动的审查范围更清楚，样式差异不再全部落在一个文件中。
- 组件按路由或能力延迟加载时，模块 CSS 有机会跟随组件加载，降低首屏无关样式的解析范围。
- 主题、响应式和共享控件可以建立更明确的责任边界。

拆分的主要风险：

- 当前样式是全局 CSS，很多规则通过选择器顺序、主题覆盖和媒体查询顺序共同生效；直接移动规则可能改变级联结果。
- 多个测试会直接读取 `styles.css` 文本检查滚动、窗口化、主题和布局约束，拆分后必须同步调整测试读取方式。
- 组件级导入已经存在，若再增加一层聚合导入，可能重复加载同一文件或制造难以追踪的顺序。
- 不同模块共享 `.button`、`.field`、`.status-badge`、`.page-header` 等全局类，按文件名切割而不先定义层级，会把依赖隐藏起来。

推荐的拆分顺序：

1. 先保留 `styles.css` 作为唯一入口，提取不依赖业务组件的基础层：主题令牌、字体、重置、全局焦点、滚动条和动效令牌。
2. 提取应用框架层：窗口壳、侧栏、顶栏、主导航、页面工作区和窗口控制。
3. 提取共享组件层：按钮、表单、页签、分段控件、页面壳层、状态徽标、通知、对话框和空状态。
4. 提取聊天层：会话列表、消息、Composer、任务条、工具活动块、审批和聊天响应式规则。
5. 提取仍留在全局文件中的工作区层：知识库、魔法笔记、智能心跳、活动记录和远程主机；已有独立文件的模块先不重复迁移。
6. 最后整理主题和响应式覆盖，把每条覆盖规则放回它所约束的基础层或模块层，并保留统一入口和稳定加载顺序。

实现约束：

- 不采用 CSS Modules 或大规模命名改造作为第一步，避免同时改变类名、测试选择器和业务组件。
- 每次只迁移一个边界清楚的区块，迁移前后运行对应页面测试和截图检查。
- `styles.css` 初期保留为聚合入口或兼容入口，待所有直接读取它的测试改为读取聚合后的实际样式集合后，才考虑更名或删除。
- 不在拆分任务中顺便重写颜色、圆角、间距或主题语义；视觉改动与文件迁移分开，便于定位回归。
- 任何按需加载收益必须通过构建产物和首屏测量验证，不能仅凭文件数量宣称性能改善。

建议优先级：P1，安排在共享 UI 状态和应用框架的视觉行为稳定后实施。第一步只做基础层和应用框架层迁移，完成级联快照、主题、响应式和现有 CSS 结构测试后再继续。

调整后的组织方式：当前拆分先以领域级入口为主，细文件作为领域内部实现。`styles.css` 只直接引入以下领域入口：

- `styles-foundations-entry.css`：基础令牌和全局控件。
- `styles-app-shell.css`：应用壳、侧栏、顶栏和窗口控件。
- `styles-chat-entry.css`：会话列表、任务条和执行反馈。
- `styles-workspace-entry.css`：页面壳层和共享工作区原语。
- `styles-knowledge-entry.css`：知识库壳层、文档、图谱、设置和任务。
- `styles-operations-entry.css`：运行记录等运营工作区的公共入口。

领域内的细文件暂时保留，后续在对应功能调整稳定后再合并删除。这样 Agent 先按领域定位入口，需要处理具体组件时再进入领域内部文件；CSS 顺序仍由入口文件集中控制。

当前状态：领域入口已建立并通过共享、聊天、知识库、平台工具和应用壳测试；全量测试曾因测试总量超过 5 分钟未完成，随后单独修复并通过 `AppSidebarLayout.test.ts` 的 5 个布局断言。类型检查和 Renderer 构建通过。

补充验证：魔法笔记、魔法笔记窗口化、智能心跳和运行记录相关 219 个用例通过。主 `styles.css` 的历史重复规则仍在分批清理，当前不把领域入口整理标记为最终删除旧规则。

最新收口：已从主文件删除页面壳层、页面标题、页签、分段控件、空状态和运行记录页面壳层的重复规则；共享原语、知识库和运行记录相关测试继续通过。测试读取方式已按领域入口补齐。

## 11. 完整收口计划

本节定义剩余工作的一次性执行范围。后续按阶段连续执行，不把每个小文件拆成独立需求；每个阶段完成后只保留验证结果和阻塞项。

### 11.1 阶段一：领域入口和旧规则清理

- 保持 `styles.css` 只负责全局剩余规则和领域入口顺序。
- 对照 `styles-foundations-entry.css`、`styles-chat-entry.css`、`styles-workspace-entry.css`、`styles-knowledge-entry.css` 和 `styles-operations-entry.css`，删除主文件中已经被领域文件完整接管的重复规则。
- 删除旧的页面壳、会话列表、任务条、执行反馈、知识库壳层、文档、图谱和运行记录页面壳规则。
- 保留跨领域主题覆盖、强制颜色模式、全局响应式和仍未归属的业务规则。
- 删除后逐组运行对应测试，确保聚合入口中的 CSS 顺序与原行为一致。

## 4. 首批实施计划：顶部会话标题


第一行是主要标题，第二行是低一级的范围上下文。项目名称不作为可编辑控件，也不替代左侧项目切换器。

### 阶段 B：建立 UI Gallery

- 以现有共享组件和真实业务状态为内容，规划一个开发或内部验证入口。

#### 批次 2：导航和工作区信息架构，优先级 P1

- 评估并调整主导航的用户任务分组，保留现有路由和权限语义。

- 验收覆盖首次进入、切换项目、切换工作区、打开右侧工作栏和恢复未保存状态。

#### 批次 3：UI Gallery 与共享组件回归，优先级 P1

- 建立公共组件和状态的集中检查页面。
- 使用真实令牌和生产组件，不增加页面专属颜色、圆角、阴影或字体栈。

- 验收以组件语义、可访问性和截图差异为准。

#### 批次 4：复杂工作台密度调整，优先级 P2

- 逐页检查知识库、魔法笔记、智能心跳、活动记录和右侧助手栏。

#### 批次 5：主题、字体和密度扩展，优先级 P2

- 基于 Gallery 和截图基线评估字号、字体组合、控件高度和页面间距。
- 保持现有浅色、深色和磨砂特效语义，只有证据显示层级或可读性问题时才调整令牌。

## 9.3 通用控件加载顺序修复

- 问题：宽屏知识库页面出现“返回知识库列表”按钮。原因是拆分后按钮、输入框、开关等通用样式排到了最后加载，覆盖了页面写的同等优先级样式，例如知识库用 `display: none` 隐藏这个按钮。同类回归还有：知识库来源的“已同步”“失败”状态颜色、设置里危险区域的背景、知识图谱小按钮、开关行，以及分块编辑框的尺寸。
- 修复：通用控件样式移入 `styles-workspace-common.css`，加载顺序调整为基础样式之后、所有页面样式之前；各文件内部恢复拆分前的规则顺序。`styles.css` 现在只保留全局层，不再包含通用按钮样式。
- 加载顺序调整后，约 20 处页面原本写好、但之前被通用样式盖住的尺寸会开始生效，例如任务中心“新建”按钮、工作栏浏览器工具按钮、标签管理按钮、扩展卡片开关和主机状态徽标的紧凑尺寸。另外有 3 处必须保留原有表现，已单独处理：AI 评论和工作栏预览中的 Markdown 段落与代码块继续使用共享 Markdown 样式；OCR 模型删除按钮禁用时继续显示灰色。
- 逐项检查这约 20 处变化后的处理：
  - 保留紧凑尺寸：任务中心“新建”、标签管理按钮、OCR 模型仓库按钮、扩展市场总开关和扩展卡片开关、主机状态徽标。它们位于工具栏、卡片和菜单行内，紧凑尺寸更合适；高度不低于 26px，符合 UI-DESIGN 中紧凑区域的要求。
  - 保留：工作栏浏览器工具按钮现在是 36px 正方形图标按钮，此前被通用按钮的内边距撑宽；反馈和扩展配置中的多行输入框恢复为 116px 和 120px 的多行高度，此前被压到 38px；新建项目表单输入框与同组其他输入框的内边距保持一致。
  - 补充完善：本机客户端的“停止”和“确认停止”按钮使用紧凑芯片尺寸，同时保留危险色和危险色悬停效果；禁用状态显示为不可点击。此前这两个按钮被渲染成普通尺寸的危险按钮，和同一行的“打开浏览器”“取消”按钮高度不一致。
- 新增回归测试：检查通用按钮先于知识库返回按钮加载，并检查通用规则先于危险区域、知识库开关和来源状态规则加载。
- 验证：类型检查和构建通过；Renderer 全量 1,966 个用例通过。另有 2 个 `App.test.tsx` 用例失败，在 HEAD 上同样失败，与本次修改无关。14 个 Electron 布局测试逐个运行全部通过。真实窗口截图仍需先关闭本机运行的 GoodBuddy。
