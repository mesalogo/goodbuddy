# 常规 PR 模板

适用于小功能、体验改善和维护修复，例如会话置顶、完成提示和浏览器交互改善。
开头概括本轮更新，再按重要性说明变化。可以介绍不同功能，不要求拼成一个故事。
只有两三个小变化时，可以去掉小标题，用几段文字写完；纯维护更新也可只保留更新日志。

写作前在本轮 `review.md` 记录比较区间、入选变化、事实来源和使用限制。
方括号是编辑提示，发布前删除或替换。不规定字数，各项篇幅不要求一致。

```markdown
# GoodBuddy 更新：[本轮最值得关注的一两项变化]

[一两句话说明本轮更新了什么，直接进入内容；信息重复时省略。]

## [变化名称]

[说明现在能怎样操作。必要时用一句话交代原来的不便，不重复解释价值。]

[有助于理解时配实际截图和简短图注。]

## [变化名称]

[同上，按重要性排序。]

[其他小改动可合并成简短列表，不必每项单独成节。]

[可用版本与下载入口。]
[必要的升级说明，完整更新日志链接。]
```

审校时删掉空泛开场、虚设场景和总结口号。不为小修复强行写产品意义，不把旧能力写成新增。
明显的界面变化可以配图，其余直接说明。配图按[截图步骤](./screenshot-guide.md)取得，
完整流程见[工作流](./README.md)。
