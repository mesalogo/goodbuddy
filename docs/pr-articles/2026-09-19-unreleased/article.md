魔法笔记可以在同一页里写字、画图、放图片，也能导入 PDF 做批注。聊天和知识库中的文档则可以查看解析后的图文，选取插图继续提问，保存的附件在重启后仍能回看。

这次更新以画布笔记和文档处理为重点，同时加入应用管理、Agent 执行清单和远程 Continue。应用管理也将成为后续私有化应用市场的入口。以下内容来自尚未发布的开发版本，正式版本号和下载入口待定。

## 新增功能

### 画布笔记：文字、手写和图片写在同一页

原有富文本笔记之外，魔法笔记新增了分页画布。打开一本笔记，在顶部输入区选择“画布”，就可以从空白、横线、方格或点阵纸张开始记录。

画笔适合随手写画，高亮笔用来标记重点。正文可以键入并跨页排版，图片和浮动文字可以放到页面上，再移动、缩放或旋转。需要新的一页时可以继续添加，图文内容一起保存在这条画布记录中。

>
> 建议图注：同一页画布中混排文字、手写标记和图片，保存后仍可继续编辑。

#### 在 PDF 上批注，保存后继续编辑

PDF 可以作为底版导入，在原页面上圈画重点、补写说明。点击“保存”后，以后仍能从这条记录的“编辑”入口继续修改。需要分享时，可以导出带批注的 PDF。

> **【待补图 02｜建议｜PDF 批注】** 在这里放一份虚构 PDF 导入画布后的截图，展示原文、高亮和补充文字。计划文件：`assets/02-pdf-annotation.png`。若改用导出文件截图，图注须明确是导出结果，不能暗示仍有可搜索文字层。
>
> 建议图注：将 PDF 作为底版，在原页面上圈画重点并补充说明。

导出的每一页由背景、文字和批注合成图像，不保留原 PDF 的可搜索文字层；需要检索或编辑原文时请保留原文件。画布导入扫描 PDF 本身不会触发 OCR，也不保证将手写内容转换成文字。

编辑和阅读都支持 25% 到 300% 的缩放，点击百分比回到 100%。“适应宽度”会随窗口或侧栏宽度调整，只改变观看大小，不改保存内容和导出尺寸。

笔记仍需手动保存。离开或切换编辑对象时会提醒未保存内容，但不提供自动保存或崩溃后的草稿恢复。每条画布记录最多 50 页，单个导入 PDF 上限为 32 MiB，单张图片上限为 20 MiB，其他限制见[画布说明](../../../src/renderer/src/magic-canvas/README.md)。

> **【待替换 R02｜画布说明链接】** 对外平台发文时，将上方仓库相对链接换成最终发布版本对应、可公开访问的完整文档链接。若仅在仓库阅读，可保留相对链接；不要编造使用文档地址。

#### 请 AI 评论画布内容

书写、保存和导出无需模型。请求 AI 评论时，默认发送当前画布的第 1 页，可在魔法笔记设置的“发送画布页数”中选择 1～8，按页面顺序发送前 N 页；不足 N 页时发送全部页。这个数量指画布页数，不是笔记记录数。支持图片的默认模型收到所选页的图像和文字；纯文字模型只分析同一范围的文字，并标注未查看笔迹、图片和布局。所选页只有图像、没有可提取文字时，需要支持图片的默认模型。

> **【待核对 C01｜最终版本的画布分析页数】** 核对最终发布提交是否包含“默认 1 页、可选前 1～8 页”的设置。若行为不同，按该版本的真实行为替换上一段，不直接沿用旧稿。此处不要求补 AI 结果图；没有真实模型生成证据时，不放模拟评论截图。

可以手动分析，也可以设为保存后自动分析。画布的“即时”模式同样需要手动点击，不会每画一笔就调用模型；分析失败不会撤销已经成功的保存。内容会发给配置的模型服务，多页画布会携带多张图片，费用按该服务计算。

#### 升级前请备份笔记

这次升级会把已有笔记正文和资源迁移到本地文件，数据库继续保存目录、索引等信息。**升级前请先备份。升级后的笔记备份要同时保留数据库和相邻的 `notes/` 目录。**

建议关闭应用后备份，恢复时将两部分一起恢复。只复制数据库，无法找回新版笔记正文和图片。目前没有一键备份按钮，具体要求见[备份说明](../../features/magic-notes/technical-design.md#backup-and-restore)。

> **【待替换 R03｜备份说明链接】** 对外平台发文时，将上方相对链接替换为对应发布版本的公开备份说明链接，并确认能直接定位到备份章节。保留正文中的数据库与 `notes/` 成套备份提醒，不能用一个下载链接代替。

### 文档处理：查看图文、选图提问，之后还能回看

从聊天附件或知识库打开解析结果，可以查看正文中的文字、HTML 表格和已保存的插图。“图片”页集中展示提取出的图片，“详情”页记录本次解析的配置、耗时和警告，方便对照文件检查结果。

文档中的某张图需要单独讨论，可以在预览中选取，添加到目标会话，再交给支持图片输入的模型。选图只加入草稿，由你补充问题并发送。会话保存的是独立副本，之后删除或重新解析源文档，不会影响这张图片。

> **【待补图 03｜必补｜文档图文预览与选图】** 在这里放正常聊天导入后的真实解析预览，显示正文／图片入口及选图加入会话的操作或实际结果；不能用没有选图能力的“设置测试”窗口替代。计划文件：`assets/03-document-to-chat.png`。若图注提到 PaddleOCR-VL，必须使用该服务实际返回的结果。
>
> 建议图注：查看文档解析出的图文，选择需要讨论的插图加入会话草稿。

聊天文件会随草稿、消息或排队请求保存。只要这些记录仍引用附件，重启后就能重新打开文件和已有解析结果，回看无需再次做 OCR。历史附件要重新解析时，可以复制到当前草稿，原消息保持不变；排队中的附件需要修改，则先恢复到草稿。

知识库文档也能使用当前设置重新解析。新结果成功后才替换正文、分块和图片，失败时保留旧结果。

附件保存从本轮版本开始生效，旧消息中原本没保存的文件不会自动补回。

#### 扫描资料可以接入团队的 PaddleOCR-VL 服务

对于扫描 PDF 和图片中的文字，本轮新增 **HTTP PaddleOCR-VL 接入**。已有这项服务的团队，可以将它用于聊天附件和知识库导入，桌面端无需为此下载本地 OCR 模型。原有本地解析仍然可用。

在“设置 → 文档解析”选择“远程服务”，填写地址，并按部署选择无需认证或 Bearer API Key。服务配置共用，聊天和知识库可以分别选择解析方式：自动模式先读 PDF 的原生文字，仅将需要 OCR 的页面交给服务；高保真模式可以发送整份 PDF；快速文本／快速索引模式不上传 OCR 内容。PPTX 保留原生文字，并按设置识别幻灯片直接引用的内嵌图片。

内容过滤可以沿用服务默认、全部保留，或自行决定是否保留页眉、页脚、页码等内容。跨页表格可启用合并，整理结果保留来源页供核对。方向分类、去扭曲、图表与印章识别、标题层级调整也有配置入口，实际效果取决于文件和服务部署。

保存后，可以从“测试解析”选择聊天或知识库场景，用实际文件检查结果。测试文件不会加入正式会话或知识库；“检查连接”只确认服务可连接，不代替解析测试。

普通聊天图片默认仍以图片发送。只需要文字时，可选择“提取图片文字”，也能切回发送原图。手动提取会调用已保存的 OCR 来源，即使聊天采用快速文本模式。HTTP OCR 会把需要识别的页面或图片发到配置的服务，跨页整理还会增加请求，请确认资料使用范围和服务费用。

### 应用管理：当前管理内置应用，后续连接私有应用市场

侧栏底部的应用中心提供统一入口。进入“管理应用”，可以搜索、打开内置应用，修改可选应用设置，并调整四个应用的顺序。菜单和侧栏采用同一份保存后的顺序。

知识库和智能心跳始终显示；魔法笔记、本机推理监控可以设置是否启用、是否常驻侧栏。新配置中的本机推理监控默认不常驻，需要时从应用菜单打开，已有设置会保留。

>
> 建议图注：在应用管理中打开、设置和排列内置应用，侧栏使用同一份保存后的顺序。

本机推理监控可以查看语音识别、OCR、向量等本地服务的状态，执行各服务实际支持的启停、重启或模型加载、释放。独立向量进程可显示 CPU 和内存占用；共享进程的服务会说明无法独立统计的原因。它不管理远程 HTTP OCR 服务，关闭监控窗口也不会停止本地服务。

**后续的应用市场将支持组织私有化部署。** 按规划，团队可以部署自己的市场，用户配置该来源后获取组织提供的应用，不必依赖公共市场。当前这一轮先提供内置应用管理；市场目录、应用获取与安装属于后续建设内容，尚未上线。应用市场来源也不会替换模型、桌面更新或 Runtime 的下载来源。

### Agent 执行清单与远程 Continue

OpenCode 和 Continue 提供的原生执行清单会显示在对话顶部，列出条目状态和完成数量，可以展开或收起。清单随对应消息保存，原来的工具活动记录仍然可查，本地和远程的 OpenCode、Continue 都支持。

清单由 Runtime 更新，用户只能查看，不能手动勾选。请求结束或取消后，条目保留实际状态，剩余事项不会自动变成“已完成”。Runtime 没有提供清单时，普通回复里的列表也不会被当成执行进度。

远程项目新增 Continue 选择。安装匹配的 GoodBuddy Agent／Runtime 包后，可以从桌面发送请求，由远程主机执行，支持 Ask、Execute、停止当前请求及应用重启后续发；取消后也能在同一对话接着使用。仅更新桌面应用还不够，正式远端包及版本组合以发布说明为准。

## 功能改进

### 笔记记录连续浏览

同一本笔记的文字和画布记录连续排列。左侧索引显示画布首页缩略图和页数，点击后滚动到对应记录，正在写的内容留在原处。索引与 AI 评论区可以分别收起，宽窗口下还可以调宽。保存一条新记录后，顶部输入区清空，供下一条使用。

### 常用操作更集中

应用管理采用紧凑单列列表，打开、设置和排序操作放在对应应用旁。聊天与图片预览的下载入口统一为带提示的图标按钮。顶部移除了重复的模型／Runtime 状态标记，模型选择和切换反馈保留在输入区，自动状态检查失败仍通过通知提示。

## 问题修复

- **长会话历史被截断**：修复连续发送时只保留最近 500 条消息的问题，追加消息会保留已有历史。模型的上下文窗口和既有压缩规则不变，也不会恢复此前已经丢失的内容。
- **较早会话找不到**：会话列表和搜索不再局限于最近 100 个会话，较早的未归档会话也能列出和搜索。
- **取消后紧接着发送异常**：修复 OpenCode 上一次取消影响下一次请求的问题；已结束的回复也不会因迟到的状态更新重新显示“停止”按钮。
- **弹窗遮住菜单和通知**：打开设置或其他对话框时，所属菜单和通知可以正常显示、操作，保留键盘导航和关闭后的焦点返回。
- **网页的新窗口链接无响应**：修复内置浏览器直接拦截这类链接的问题，现在会在 GoodBuddy 管理的标签中打开；AI 点击产生新标签后，后续浏览器操作会跟随新页面。
- **知识图谱抽取提前耗尽输出预算**：移除额外的固定 8192-token 限制。OpenAI 请求由模型服务决定输出上限，Anthropic 使用模型连接配置；服务自身的限制、超时和取消仍然有效。
