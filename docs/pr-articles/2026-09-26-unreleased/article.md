GoodBuddy 这一版完成了三条连接：用故事图谱整理持续推进的工作，用 Telegram 在桌面之外发起对话，用 Obsidian 连接已有的本地笔记。故事图谱帮助人和助手回看决定、依据与后续变化；Telegram 适合在手机或其他设备上继续处理文字请求；Obsidian 则让原有笔记仓库可以直接参与对话。

当前配套版本为 Desktop `0.15.13` 和 Agent `0.15.6`。远程项目使用这些能力前，请先升级桌面端，再更新 Host 环境。

## 故事图谱：从工作记录中看清一件事如何发展

### 工作回顾留下进展和依据

监督者可以按全局或项目范围回顾最近一天、数天或指定日期内的工作记录，整理出工作总结、变化和未解决事项，并按故事列出推进、新出现和结束的内容。回顾结果会保留范围与生成时间，方便之后回看。

每条结论都可以继续追溯到事件、实体、关系和来源正文。打开来源后，可以检查模型依据的是哪段讨论，再决定是否确认、改名或调整关系。

### 故事、经验和时间螺旋

事件可以归入持续发展的故事，按项目、功能和子线索浏览。用户可以调整故事名称、合并重复故事、移动事件或撤销调整。故事中的经验会保留适用条件、形成依据和后续应用记录，也可以人工编辑、合并或删除。

故事图谱提供平铺和时间螺旋两种视图。时间螺旋按事件时间和消息密度展示工作如何交错推进，适合观察停顿、延续和阶段变化；平铺视图适合查看对象之间的关系。设备不适合 3D 浏览时，可以切换回平铺视图。

### 助手可以接着既有决定继续工作

当用户追问“此前为什么选这个方案”或“这项决定后来怎样修改”时，助手可以查询已经保存的故事、经验、事件、实体、关系和回顾结果，再读取相关来源。查询发生在需要时，不会在每次对话中自动注入整张图谱。

输入区可以单独控制当前会话是否允许访问故事图谱。查询默认使用当前项目，也可以指定全局或项目集合；故事图谱工具只读取已有记录，不会因为一次查询重新运行回顾或修改图谱。

### 智能心跳持续整理变化

设置每日或每周计划后，智能心跳会处理新增和变化的工作记录，更新故事图谱，并提出未决事项、分歧、修订、候选约定、长期没有进展的故事和可能适用的经验。没有新的工作来源时会跳过事实提取；建议生成失败可以单独重试，已保存的回顾和图谱仍然保留。

## Telegram：从私聊继续处理任务

配置自己创建的 Telegram Bot、数字用户 ID 白名单和通道项目后，可以通过 Telegram 私聊发送文字问题或任务。GoodBuddy 会沿用该项目的 Runtime、模型和工作目录处理请求，并把最终文字回复返回到 Telegram，桌面端同时保留会话记录。

首次配置时可以先留空发送者 ID，启用并保存通道；连接 Bot 后发送 `/start` 和 `/whoami` 获取自己的数字用户 ID，再填入白名单并保存。连接支持断线恢复和停用取消，桌面应用需要保持运行并能连接 Telegram。

当前通道面向单个 Bot 的普通私聊和文字请求。群聊、媒体输入和附件发送仍在桌面端处理，图片等附件结果需要回到桌面查看。

## Obsidian：直接连接已有笔记仓库

在“设置 → 能力与工具 → MCP”的 Obsidian 卡片中，可以选择本机已注册的仓库或限定文件夹，测试连接并分配给所用 Runtime。无需启动 Obsidian，也无需安装插件或配置 REST 服务。

接入后，可以让助手搜索和读取笔记，也可以把讨论结果写回仓库。支持追加、局部修改、目录浏览，以及标签和属性操作。笔记仍保存在原仓库，不会自动复制到 GoodBuddy 知识库。

Obsidian 接入默认关闭，启用后只在配置范围内读写。当前支持直连模型及 GoodBuddy 管理的本机 OpenCode、Continue 聊天；读出的笔记会随当前会话交给所选模型处理。

## 其他改进

### 输入区和 Runtime 控制

上下文来源、专家角色、模型和 Runtime 控制收进输入区工具栏。故事图谱与知识库使用同一个上下文入口，OpenCode 和 Continue 的运行配置放入独立弹窗。窄窗口下仍能按可用空间排列，弹窗支持自动聚焦、外部点击关闭和 Escape 返回焦点。

### 笔记、文件和图表

魔法笔记支持插入和编辑表格，表格与其他富文本一起保存；笔记支持标签筛选、标签管理和列表与正文双栏浏览。聊天回答可以保存到笔记并返回原会话，工作区支持批量导入本地文件到本地或远程项目，Mermaid 图表可以导出完整 PNG。

### Runtime、会话和日常操作

项目和会话集中到同一个菜单，Runtime 与模型可以分别按会话、项目和全局配置解析，也可以在当前会话临时切换。聊天历史、侧栏和长消息减少重复渲染，阅读位置、展开状态和流式回复更稳定；桌面通知、磨砂外观和任务用量可以分别设置。

### 请求、存储和故障处理

SQLite 存储、后台读取、请求取消和并发处理路径已经合并调整，减少主进程等待。直连模型支持手动压缩上下文，工具执行失败后可以继续对话；长请求结束、取消或失败时会正确回收工具授权。监督回顾支持暂停、继续、取消和失败后重试，远程 Runtime 启动和本地 OpenCode 连接也补充了取消与恢复处理。

## 升级提示

升级前请关闭应用，并备份完整用户数据、设置、数据库、WAL 文件和相邻的 `notes/` 目录。当前数据库格式为 62，0.15.13 之前的客户端不能直接打开新版数据库，回退需要使用升级前的备份。首次转换较大的数据库时需要等待；高频本地保存调整了磁盘同步策略，断电时可能丢失最近尚未同步的写入。
