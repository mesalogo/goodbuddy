# GoodBuddy 更新：飞书、企业微信与文档引用

GoodBuddy 这轮更新接入了飞书和企业微信的办公工具。在聊天里，可以请助手查阅平台文档、整理内容，再把结果写回；输入 `@` 选择文档，就能指定这次讨论要用的资料。消息连接和工具设置也集中到了应用中心。

## 新增功能

### 飞书：文档、知识库和多维表格参与对话

飞书接入后，助手可以读取和创建文档，追加或修改正文，浏览知识库与云空间，也能查询和更新多维表格记录。讨论完的内容可以直接写入飞书，后续仍在原来的文档中查看和协作。

右侧的飞书面板提供知识空间、页面和文件夹浏览，支持搜索、类型筛选、新建文档或知识库页面，以及上传本地文件。找到资料后，可以打开原文，或将它用于当前对话。聊天中的工具结果卡片会显示可识别的文档标题、操作和原文入口，便于核对助手刚才处理了什么。

飞书消息通道也已接入，支持飞书和 Lark。配置应用凭据、允许的发送者及群聊响应策略后，可以从飞书向 GoodBuddy 发起文字请求并接收文字回复，使用期间桌面端需要保持运行。

文档工具使用飞书应用身份，访问范围由应用权限和资源授权决定。接入前需要把相应文档或知识空间开放给应用；消息通道目前处理文字，不收发图片和附件。

### 企业微信：从查资料到处理办公事项

企业微信接入扩展到了办公操作。完成工具授权后，助手可以按开启的类别处理在线文档、表格、智能表格、智能页面和微盘资料，也可以使用日程、会议、待办、通讯录等工具。在线 PPT、邮件和消息操作有各自的类别开关，按需要启用。

右侧面板可以搜索文档，查看近 30 天最近浏览或自己创建的资料，浏览微盘，并新建在线文档、上传文件。文档仍保留在企业微信中，工具按授权人的身份访问和修改，沿用该身份已有的权限。

飞书和企业微信工具可用于直连模型、OpenCode 和 Continue 对话。消息会话是否可以使用这些办公工具，需要在应用设置中单独开启。企业微信工具支持 Windows x64、macOS x64／arm64 和 Linux x64／arm64。

### 用 `@` 指定这次讨论的文档

在输入框里键入 `@` 和关键词，可以搜索已接入的飞书或企业微信文档。选中后，文档以引用标签留在输入区，和问题一起发送；一次可以选择最多五份资料。

例如，选中一份项目方案，再写“整理其中还没有确定的事项”，助手就会根据引用调用相应平台工具读取资料。引用保留标题、链接和资源标识，实际能读取的内容取决于文档类型、平台权限和当前 Runtime 支持的工具。

菜单跟随输入位置展开，支持键盘选择。应用已经开启、但凭据或工具类别尚未就绪时，入口会显示原因和设置位置。

## 功能改进

### 连接设置和文件查看更集中

飞书、企业微信、钉钉、微信 ClawBot 和 Telegram 现在统一列在应用中心。每个平台集中显示连接状态和设置入口，飞书与企业微信的工具可用性跟随同一个应用总开关，具体类别仍可分别选择。

聊天里的项目文件链接可以直接打开右侧工作区预览，图片也能从文件列表或聊天链接中查看。文档附件名称变成了可点击入口，用系统应用打开保存的原文件。远程项目的图片预览需要配套支持该能力的 Agent。

### 魔法笔记放宽导入与保存限制

长文本、图片、附件和多页画布不再受此前固定的内容大小、资源数量及页数配额限制。原先因超出这些配额而被拒绝的资料，可以继续导入和保存；实际处理规模仍取决于设备内存和文件内容，AI 分析也保留独立的上下文范围。

日常操作也做了几处整理：导入 Skill 不必先把来源文件夹改成与技能 ID 相同的名字；会话标题下方显示所属项目，任务条直接显示状态文字；聊天缩略导航按用户和助手角色统一配色。

## 问题修复

- 监督回顾中某个会话批次失败时，其他可处理会话仍会继续，已完成批次保留。恢复后继续未完成部分，存在失败时不会把结果当作完整回顾发布。实体引用出错时，也会说明重复、越界或对象已失效等具体原因。
- 模型请求遇到 HTTP 413 时，提示尝试压缩上下文后重试，便于处理请求过大的问题；这项提示同时覆盖直连模型和远程模型桥接路径。
- 魔法笔记切换长短内容、编辑或接收 AI 评论时，面板高度保持稳定，长内容在面板内滚动。飞书、企业微信应用关闭后，已经打开的侧栏标签仍可正常关闭。
