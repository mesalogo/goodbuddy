# Pi Runtime 产品需求

## 背景与目标

Continue CLI 的后续维护存在不确定性，GoodBuddy 需要一个可本地运行、可由宿主完全接管配置、
体积可控的替代 Runtime。Pi 提供可嵌入 SDK，官方 bundle 与当前 Continue 打包资源体积接近，
适合作为候选。

目标：用户可在现有 Runtime 选择器中选择 Pi，使用 GoodBuddy 已配置的模型和全局能力完成
编码任务，体验与其他 Runtime 一致；不支持的能力不显示入口。

## 范围

### 首版包含

| ID | 需求 |
| --- | --- |
| FR-1 | Runtime 选择器、全局/项目/会话继承和模型兼容判断支持 `pi`，规则沿用[选择合同](../../contracts/selection.md) |
| FR-2 | 使用 GoodBuddy 模型连接，支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 三种协议；真实凭据不离开 Main |
| FR-3 | 流式文本、推理、工具过程、用量、错误和终态进入现有聊天事件 |
| FR-4 | 本地文件读写、搜索；Windows 使用 PowerShell 工具，其他平台使用 Bash |
| FR-5 | 取消到达实际执行：模型请求中止，命令进程树回收，兄弟会话不受影响，随后可继续对话 |
| FR-6 | 多轮会话持久化；应用重启后按 GoodBuddy 会话恢复同一 Pi 会话 |
| FR-7 | 全局 Skills 与自定义 MCP 按 Runtime 分配生效；内置业务 MCP 与 scoped data tools 按现有授权接入 |
| FR-8 | 仅映射原生流程实际发出的 UI 交互；不注册模型结构化提问工具 |
| FR-9 | 不提供 Todo 工具或顶部清单数据源（原补齐方案撤回，保留编号） |
| FR-10 | 不提供子代理工具（原补齐方案撤回，保留编号） |
| FR-11 | 手动上下文压缩使用 Pi 原生 compact |
| FR-12 | 资源缺失、版本不符、模型不兼容和宿主启动失败给出可诊断状态 |

### 首版不包含

- 通过自建、第三方或官方示例扩展补齐子代理、Todo、模型结构化问答；OMP 对标讨论不构成启用授权。
- 跨主回复存活的后台子代理、后台命令和常驻服务管理：Pi 无原生实现，声明为不支持，
  会话顶部不生成运行任务条目。
- 托管 SSH 远程执行：首版仅本地，与 DeepSeek Harness 一致；远程入口隐藏。
- 读取用户自己的 `~/.pi` 设置、扩展、主题和 Pi 包管理器安装的扩展。
- Pi OAuth 订阅登录（如 ChatGPT/Claude 订阅）：GoodBuddy 只使用自身模型连接。

### 后续阶段

- FR-13 在终端中打开 Pi TUI：独立会话，沿用[原生客户端合同](../../design/native-client.md)。
- FR-14 图片输入。
- FR-15 托管远程执行。

## 能力声明

| 能力 | 首版声明 |
| --- | --- |
| 原生客户端 | 后续阶段（FR-13）；首版不显示入口 |
| 原生定制 | 不提供 agent/command 清单；Pi prompt template 首版不加载 |
| 结构化问答 | 无默认模型提问工具；原生 select/confirm/input 交互通道可适配，仍需产品验证 |
| Todo | 不支持，不加载官方示例或新增工具 |
| 原生子代理 | 不支持，不加载官方示例或新增工具 |
| 跨主回复后台执行 | 不支持 |
| 后台命令与常驻服务 | 不支持；命令随工具调用等待结束 |
| 上下文压缩 | Pi 原生 compact；自动压缩策略见待决事项 |
| 图片与文件 | 首版文本与工作区文件；图片输入后续 |
| 托管远程执行 | 不支持 |

## 交付与 Continue 替换判定

Pi 达到以下条件后，才评估将 Continue 从默认可选项中移除：

1. FR-1 至 FR-12 完成产品路径验收（真实 UI 到 Runtime）。
2. 同条件构建对比：安装包、安装后占用、启动时间、空闲内存不劣于 Continue 版本或差异可接受。
3. 已选择 Continue 的项目和会话有明确迁移或保留方案，不静默改写用户选择。
