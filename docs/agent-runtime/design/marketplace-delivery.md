# Runtime 应用市场交付方向

## 决策与范围

2026-10-25，用户确定将 OpenCode v2 和 Factory Droid 纳入未来应用市场的交付范围。
用户可以在市场中按需下载，也可以手动导入本地运行资源。GoodBuddy 主安装包不默认携带
这两个 Runtime 的完整运行资源，避免未使用它们的用户承担下载与磁盘开销。

本文记录产品方向，市场、安装管理和两个 Runtime 的产品接入尚未完成。统一执行与能力
验收仍以 [Agent Runtime 接入规范](../README.md)为准。本次不升级现有 OpenCode 1.x，
也不改变其他 Runtime 的交付方式。

## 用户流程

- 在线使用：打开应用市场，选择 Runtime 和目标执行 Host，查看适配版本、平台、下载量与
  安装占用，执行下载和安装；安装成功且兼容检查通过后，可在现有 Runtime 选择器中使用。
- 手动导入：在同一市场入口选择本地运行资源，检查平台、架构、版本及所需文件后完成安装。
  内网离线导入须包含运行所需依赖，启动聊天时不再临时从 npm 下载。
- 已有安装：保留检测或指定已有可执行文件的方式，由同一安装管理入口展示可用状态，
  不要求用户重复下载。用户自行安装的原文件不由 GoodBuddy 删除。

应用市场负责获取和管理运行资源；模型选择、全局 Skills/MCP 启停与 Runtime 分配仍在现有
设置中完成。下载成功只表示资源已取得，必须通过启动检查和产品路径验收才能声明可用。

## 资源与生命周期

安装按实际执行 Host 管理；远程使用时资源应位于对应 Host，桌面无需再装一份执行二进制。
同一 Host 的多个项目共享安装，会话的配置、历史和任务归属保持独立。

主包保留必要的接入和管理代码。SDK、插件及其他依赖是否随可选资源交付，按各 Runtime 的
最终宿主方案和构建测量确定；不承诺主包零增量，也不预先固定 SDK 必须捆绑主包。
OpenCode v2 的进程内 SDK 仍需遵循既有 Main 调度与受控执行进程边界。

市场使用经过适配验证的精确版本组合，并沿用已有下载源和资源管理机制。更新不替换正在
使用的文件，旧进程释放后再清理闲置版本。卸载运行资源保留用户聊天历史，不删除用户提供
的原文件；运行中的会话和后台任务须先完成或显式停止。

市场下载与手动导入共用兼容检查及启动验证。包格式、SDK 装载方式、目录布局和完整市场
UI 留待实现设计确定，本次不新增通用插件框架或独立更新协议。

## OpenCode v2 调研基线

2026-10-25 核对官方 npm、GitHub 标签和文档：

| 项目 | 当前仓库 | v2 候选 |
| --- | --- | --- |
| CLI | `opencode-ai@1.19.3` | `@opencode/cli@2.1.4` |
| SDK | `@opencode-ai/sdk@1.19.3` | `@opencode/sdk@2.1.4` |
| Plugin | `@opencode-ai/plugin@1.19.3` | `@opencode/plugin@2.1.4` |

旧包 `opencode-ai` 的 latest 为 `1.19.4`，新包使用独立发布线。现有代码中的
`@opencode-ai/sdk/v2` 是旧包的客户端入口，不代表已接入 OpenCode 2。
新版 SDK 文档描述进程内宿主、异步事件流和持久数据库配置；默认内存数据库需要在接入时
改为明确的持久化方案。上述是上游文档证据，尚未完成 GoodBuddy 实机兼容验证。

来源：[v2 安装文档](https://opencode.ai/v2/docs/)、
[v2.1.4 源码](https://github.com/anomalyco/opencode/tree/v2.1.4)、
[SDK 说明](https://github.com/anomalyco/opencode/blob/v2.1.4/packages/sdk/README.md)。

Droid 沿用[现有设计和验证记录](../providers/factory-droid/README.md)，已测组合为
Droid `0.245.1` 与 SDK `0.10.0`。市场分发前核实官方资源来源及分发条件。

## 后续验收

实现时验证市场下载、离线导入、已有安装识别、启动、更新和卸载的完整流程，同时覆盖
声明支持的平台和远程 Host。分别测量主包增量、可选下载量、安装占用、启动耗时及内存。
安装层通过后，按统一规范验证聊天、模型、Skills/MCP、问答、Todo、子代理、后台进程、
原生客户端和恢复；Droid 既有协议测试不替代产品端到端验收。
