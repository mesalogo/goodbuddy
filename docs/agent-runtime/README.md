# Agent Runtime 接入规范

本目录是 GoodBuddy Agent Runtime 的统一文档入口。本文件定义接入要求、能力声明和验收
规则；[能力矩阵](./capability-matrix.md)记录现有实现范围。具体选择、交互、存储和远程规则
由下方关联文档维护，不在各 Runtime 文档中另写一套。

规范要求不等于已实现。新增 Runtime、升级上游版本、增加原生客户端入口或扩展远程支持时，
必须按本文件核对；只有完成相应产品路径验证，才能将能力标为已支持。

## 基础接入要求

下列要求适用于每个接入的 Runtime。实现 `AgentRuntime` 接口只是其中一部分。

| ID | 要求 | 验收依据 |
| --- | --- | --- |
| RT-1 | 明确 provider、执行空间、平台、模型协议和交付方式；所有公开入口与实际支持范围一致 | 选择器、配置解析、工厂、状态、能力分配、用量归属及远程注册均已接通 |
| RT-2 | 使用现有选择解析和 Main 决定的工作区；按路径声明模型参数支持，不自行增加回退 | 实际请求的模型、协议、凭据来源和可支持参数符合已解析选择；不支持项明确说明 |
| RT-3 | 正确转换文本、工具、错误、用量及终态，保留请求/会话/原生调用归属 | 重复或迟到事件不重复正文、用量或终态，不串入其他会话 |
| RT-4 | 取消到达实际执行 owner；区分请求结束、执行结算和资源释放 | 取消后能继续请求；不误杀兄弟会话；关闭后确认所属进程与资源状态 |
| RT-5 | 明确上下文连续性是原生续接、持久会话恢复还是 GoodBuddy 历史重建 | 多轮、重启、配置切换及失败恢复按声明运行，不盲目重放未知结果的执行 |
| RT-6 | 遵循全局 Skills/MCP 启用与 Runtime 分配、业务数据范围和统一执行规则 | 真实加载/调用、未分配隔离、变更同步；无新增项目级启停或产品审批模式 |
| RT-7 | 沿用已有存储与输出 owner，区分预览、全文和原生历史 | 写入与 ACK 顺序正确，声明可完整读取的输出在历史/恢复路径仍可取回 |
| RT-8 | 固定已验证的二进制/SDK/适配版本组合，按声明交付 | 清洁目标环境可启动；版本/平台不匹配及资源缺失可诊断；临时与持久资源分别清理 |

RT-2 不要求强制翻译上游不支持的模型字段；需要在能力范围中写清不支持的协议/参数。
RT-6 不意味着所有 Runtime 天然支持全部工具类别；若承诺某类别，就必须接入并验证。

## 可选能力与产品承诺

通用规范允许 Runtime 能力不同。某个 Runtime 的 PRD 一旦承诺一项能力，该项就属于其
交付要求，不能用“可选”降低验收范围。状态使用：已实现并验证、已实现待验证、上游支持
但未接入、不支持、不适用。验证状态须有路径、版本和日期，不能只给 provider 一个布尔值。

| 能力 | 声明时必须说明 |
| --- | --- |
| 原生客户端 | Terminal/Web、执行空间、独立会话或当前会话续接、模型/能力承接范围、启动及关闭 owner |
| 原生定制 | 可发现和可执行的 agent、command、template 各有哪些，是否仅连接状态 |
| 结构化问答 | 原生问题 ID、答案/跳过映射、投递失败、取消、迟到答案与子任务归属 |
| Todo | 结构化来源、成功更新时机、替换/清空、归属、历史恢复 |
| 原生子代理 | 原生 child/call 关联、进度、结果与父子终态 |
| 跨主回复后台执行 | 会话级存活、持续事件/问题、输出读取、独立停止、配置切换和退出规则 |
| 后台命令与常驻服务 | 任务句柄/PID/进程树、输出、退出码、就绪/端口、输入支持、停止与释放 |
| 上下文压缩 | 原生压缩、GoodBuddy 摘要或不支持；实际所用模型、历史更新和用量 |
| 图片与文件 | 输入类型、大小/格式范围及输出引用；图片生成另行声明 |
| 托管远程执行 | 实际 Host 注册、模型网关、协议/能力版本、恢复/ACK、断开与退出语义 |

Skills、自定义 MCP、内置业务 MCP、浏览器、图像和 scoped data tools 要分别核对。
“支持工具”或“已分配”不能代替这些类别的实际支持。原生 inventory 也不等于可执行能力。

## 前端入口合同

### 执行对象与控制范围

接入时必须分别声明对象类型和生命周期。“后台”表示可以脱离当前前台请求继续执行，不是
唯一的任务类型；一个子代理或命令都可能被父请求等待，也可能拥有独立生命周期。

| 对象 | 身份与状态来源 | 展示及控制 |
| --- | --- | --- |
| Todo | 原生结构化清单及成功更新 | 顶部待办；无进程，不提供进程停止 |
| Subagent/子任务 | parent/child session、原生调用 ID、真实终态 | 任务进度、子工具、输出、问答；分别声明取消/继续/恢复能力 |
| 命令/进程 | 所属执行 Host、任务句柄及必要的 PID/进程树 | stdout/stderr、退出码、停止；有原生支持才提供 stdin/PTY |
| 常驻服务 | 进程归属及实际就绪信号、端口或访问地址 | 日志、访问和停止；工具返回或进程存在不等于服务已就绪 |
| 原生交互客户端 | 独立 CLI/Web 会话及其宿主 | 打开、关闭、重开；会话语义见下文 |
| 运行设施进程 | Runtime daemon、MCP server、语言服务等已有 owner | 原则上进入连接状态/诊断，不把每个宿主子进程都显示为用户任务 |

工作栏 PTY 与模型的非交互命令是不同接口。原生没有 stdin 入口时，不得用“在终端打开”
暗示能附加到已有命令；具备 TaskStop 模型工具也不等于前端可直接调用停止 RPC。

子任务至少保留父请求、原生 child/call 关联与工作区归属。子任务提问回到原提问者；失败、
取消和完成分开，单个工具失败不自动推断整个子任务失败。取消父任务是否连带子任务、关闭
Runtime 是否保留服务、停止一个子任务是否影响后代/兄弟，都必须明示并实测。

停止验收同时检查请求结果与实际执行：成功 ACK、工具 completed 或调用方取消返回不能
替代 PID/会话终态及必要的端口释放。进程树操作只针对已知所属资源，不能按名称扫描停止。
本轮 [跨 Runtime 实测](./validation/subagents-and-processes-2026-10-22.md)已发现这类差异。

入口可用性由 provider 能力、执行空间、模型配置、安装/连接状态共同决定。前端和 Main
应使用同一套明确判定；后端仍验证实际条件。不得仅凭 provider 名称展示一个必然失败的操作。
本规范先定义要求，不新增独立插件系统或第二套能力注册表。

### 在终端中打开与 Web 客户端

默认沿用[原生客户端 FR-4](./design/native-client.md#3-产品需求)：使用当前项目与模型配置
创建独立客户端会话，不自动复制或同步 GoodBuddy 聊天历史。“打开”不等于“继续当前会话”。
如增加续接能力，必须另行声明并验证 native session 关联、前台/客户端并发控制和历史归属，
不能静默改变现有入口语义。

客户端生命周期持有自己的模型桥与能力访问，不随一次聊天 turn 结束释放。收起工作栏或
切换会话不等于停止客户端；关闭终端、关闭 Web 服务、关闭浏览器标签页是不同操作。
本地终端可启动不代表远程入口已接通，普通 SSH 终端可用也不代表对应 Runtime 原生入口可用。

### 会话顶部

Todo、后台任务与定时任务复用既有顶部区域，但保持不同状态来源：Todo 是计划，后台任务
是执行，定时任务是触发规则。后台执行支持者必须提供原生身份和终态，不从普通回答猜状态。
主回复结束后保留会话级后台任务；不支持后台任务的 Runtime 不生成模拟条目。

顶部运行任务按子代理/命令/服务标明类型，复用摘要与详情布局，操作由该对象的实际能力
决定。Runtime/MCP 宿主等设施进程保留在设置和诊断中。当前这些统一展示规则是接入要求，
不表示各 Runtime 已具备统一的运行任务组件。

## 接入与升级流程

1. 核对能力矩阵和该 Runtime 的产品承诺，标出本地聊天、远程聊天、原生 Terminal/Web 的差异。
2. 固定版本并验证上游接口；协议脚本证明可行性，不替代实际产品接入。
3. 对齐 shared 合同、Main 工厂/owner、Preload、Renderer、存储及对应 Agent 路径。
4. 运行声明能力的产品验收，更新矩阵和证据；上游版本升级复验受影响路径，不只改包版本。

| 验收范围 | 必须覆盖的场景 |
| --- | --- |
| 选择与模型 | 继承、失效连接、缺少凭据、不兼容协议、自有配置、实际请求模型 |
| 聊天与工具 | 真实 UI 提交、流式/终态、读写/命令、错误、长输出与用量 |
| 全局能力 | 已启用/禁用及已分配/未分配，多会话配置变更与新会话继承 |
| 会话生命周期 | 多轮、重启、设置替换、取消时机、迟到事件、兄弟请求与清理 |
| 交互能力 | 问答回传、Todo 替换/清空、子任务归属、后台独立停止及恢复 |
| 进程/服务 | 等待/后台行为、父请求结束与中断、退出码、输出、stdin/PTY 声明、目标/兄弟隔离、PID 退出与端口释放 |
| 原生入口 | 实际按钮到 CLI/Web 可用、目录和模型、独立历史、重复点击、关闭/重开 |
| 远程路径 | 当前源码在共享 Linux x64 Host 验证实际模型/工具、受影响的断开/恢复和生命周期 |
| 交付与性能 | 平台资源、离线/下载声明、进程实际退出；性能按既有预算与测量程序 |

记录包含源码状态、平台、二进制/SDK 版本、模型协议、执行入口、真实请求次数、清理结果及
未测范围。退出码、schema、mock 或一次初始化成功都不能单独证明完整接入。

## 当前待对齐项

截至 2026-10-22 的源码核对，已有 Runtime 尚未全部满足上述规范；详细证据见能力矩阵。
优先修正入口可用性与执行路径不一致、独立客户端被误解为续接会话、能力与路径支持范围
不明确的问题。Droid 继续以此规范对齐，不因上游接口已测通就直接添加产品按钮。
